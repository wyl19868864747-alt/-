# Action Camera Vector｜回归测试

目的：验证高速动作/打斗任务会把动作方向编译成摄影机响应，而不是堆叠“甩镜、环绕、震动、高能”等词。

## Case 1｜冲刺对攻

输入：
> 两个人高速迎面冲刺，做一个有压迫感的打斗开场。

PASS：
- 先建立双方距离与运动方向；
- 选择低位/平视推进、跟拍或反向后退中的一个主要响应；
- 前景掠过或背景方向性模糊承担速度感；
- 不因“高速”自动加入环绕、Roll、Zoom、持续Shake。

FAIL：
- 同镜同时推拉、环绕、滚转、变焦；
- 只写“强钩子/高能/大片感”。

## Case 2｜扫腿命中并击退

输入：
> A横向扫腿命中B，B被踢退。

PASS：
- 摄影机先沿扫腿攻击弧线跟到落点；
- 接触发生后B才失衡/后退；
- 命中点允许极短锁住或减速；
- 后续沿受力方向展开空间。

FAIL：
- B在接触前先飞出；
- 全程持续Shake；
- 用“0.15秒凝滞、0.3秒震动”作为主要执行逻辑。

## Case 3｜复杂连续攻防

输入：
> 两人连续拳腿互换、腾空、落地、再次追击，希望非常快。

PASS：
- 先判断单镜负载；
- 高空三维动作、攻防换位和多个命中点同时出现时主动拆镜；
- 用动作方向、速度、视线、遮挡或声音保持动接动；
- 每镜只保留一个主要动作—镜头任务。

FAIL：
- 默认强制一镜到底；
- 人物多轴旋转 + 摄影机360环绕 + Roll + Zoom + 大幅升降同时出现。

## Case 4｜高速运动模糊

输入：
> 打得非常快，要很多拖影。

PASS：
- 把速度转译为前景掠过、背景方向性运动模糊、视差和速度差；
- 主体脸部、躯干轮廓和关键接触点保持可读；
- 若拖影不是必须，主动减少。

FAIL：
- 人物整身长拖影、多重残影、五官拖拽；
- 用残影代替真实动作轨迹。

## Case 5｜简单一镜到底可保留

输入：
> 一个人冲过走廊，转角追上目标并把门推开，全程单镜。

PASS：
- 世界路径清楚、主运动方向连续时允许一镜到底；
- 摄影机保持一种主要关系，必要时只有短促修正；
- 推门遵守接近→接触→门响应→通过的物理链。

FAIL：
- 因为“一镜到底”自动添加复杂环绕；
- 摄影机无可解释路径穿墙或瞬移到另一侧。

## Case 6｜战斗尾帧继续下一击

输入：
> 这5秒不要结束战斗，要自然接下一段。

PASS：
- 尾帧停在下一动作前摇：重心、视线、手脚准备位置已建立；
- 摄影机减速、略拉开或停稳，让下一段有启动空间；
- 背景对手保持上一动作的结果状态。

FAIL：
- 角色突然摆英雄Pose；
- 上一击结果未完成就重置站姿；
- 结尾人物和敌人位置关系跳变。

## 总验收

动作类输出至少满足：
`动作矢量可读 → 摄影机响应有原因 → 接触先于反作用 → 一个镜头一个主要任务 → 复杂时拆镜 → 尾帧可承接`
