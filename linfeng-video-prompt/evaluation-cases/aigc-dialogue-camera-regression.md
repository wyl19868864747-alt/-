# AIGC 原生视觉事件 × 自然对白 × 镜头耦合回归

本文件记录文本级验收，不冒充生成视频通过。

## Case A｜对白“蹦豆”

错误：
“Really?” → “Sure.” → “Plastic.” → “Fine.” → “Prove it.”

失败原因：
句数存在，但多数只是孤立关键词；相邻台词没有把上一句的意思、动作或误判带入下一句，角色像按按钮轮流发声。

修正：
“That’s your big scare?” → “You definitely flinched.” → “I barely moved.” → “Then go touch it.” → “Fine, watch me.”

验收：
- 大多数台词是自然口语意群，而非连续1–2词碎片；
- 回复明确承接上一句／上一动作；
- 句长有变化；
- 不为了每次切镜强行结束一句；
- 时长仍通过 voiceover-control 容量核算。

## Case B｜普通现实中的连续不可能变装

输入：
普通公共交通车厢，一名人物保持原座位；前景手机显示目标服装。人物服装在原位连续替换，背景和旁观者不变。

必须设计：
1. 现实底盘稳定：同一人物、座位、背景、窗光、旁观者。
2. 手机／点按是可读触发。
3. 只破坏“服装可在原位自动生成／替换”这一条现实规则。
4. 变化有起点、传播方向、中间态、完成边界；不能闪白后直接换装。
5. 摄影机以见证变化为主：变化已经读得清时保持稳定，必要时轻微跟随传播前沿。
6. 变化完成后人物或旁观者才反应，证明异常发生在现实场景。
7. 第二次变化必须改传播方式、材质、方向或后果，不能平级复制。
8. 触发声、传播声、完成落点与画面事件同步。

失败：
- 整个车厢同时奇幻化；
- 人物身份／座位／背景一起重置；
- 大面积闪白／粒子遮住全过程；
- 运镜与变化没有因果，只是同时“很炫”；
- 第二次只是换颜色重复第一次；
- Prompt直接写“视觉奇观、魔法感、AIGC感”而没有可见机制。

## Case C｜运镜有动作但没有新增信息

输入：
人物从前景走向门口，随后门后出现新信息。

验收：
- 跟拍服务位移和距离变化；
- 到门口后横移／短弧移利用门框遮挡揭示门后信息；
- 若改成随机环绕、删除后画面信息完全相同，则判运镜装饰化；
- 声音触发和镜头响应顺序可解释。

通过状态分开记录：
文本规则通过 ≠ 实际生成视频通过。
