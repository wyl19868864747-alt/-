# Seedance 2.5：任务与能力适配

## 1. 能力证据与入口

先认清用户实际使用的产品入口与模式，普通参考、首尾帧、视频编辑、延长、动作参考和白模控制有不同继承关系。可用参数以该入口的当前文档/界面为准，不把一个API的字段直接发给另一个网页产品。

截至2026-09-05读取的官方介绍：Seedance 2.5支持最长30秒生成，并介绍了图片、视频、音频引用、编辑、延长和白模等控制；官方展示的参考容量包括最多30张图片、10段视频、10段音频。具体组合、分辨率、文件大小和模式支持仍核对实际入口。

官方来源：
- [Seedance 2.5 产品页](https://seed.bytedance.com/en/seedance2_5)
- [官方发布与控制方式介绍](https://seed.bytedance.com/en/blog/one-take-creation-flexible-referencing-introducing-seedance-2-5)
- [火山引擎对应API文档](https://docs.volcengine.com/docs/6492/2595411?lang=zh)

这些来源不证明本技能的七段式一定优于其他写法，也不证明模型精确理解IRE、饱和度百分比、设备名或每个时间戳。本文的自然语言、少变量与分层写法是可测试的工作约定，不冒充官方硬要求。

## 2. 选择正确模式

| 输入/任务 | 提示词重点 |
|---|---|
| 从零/普通参考生成 | 写目标成片；参考逐一声明主要职责，文字补当前动作与关系 |
| 首帧/首尾帧 | 以实际支持的首尾角色传入；描述起止之间如何到达，不另写互斥首尾状态 |
| 多独立关键帧 | 声明图片顺序和节点用途，写动作、机位和状态怎样连接；不承诺逐像素复刻 |
| 多宫格故事板 | 提供镜头顺序与构图方向，文字补动作与连续性；画面小字不是可靠参数接口 |
| 动作/运镜参考 | 只提取指定动作/轨迹/节奏，人物与商品身份另设真源 |
| 视频编辑 | 指定修改区间、A→B、保留项和局部适配；不把编辑写成从零重新拍一遍 |
| 延长/转场 | 继承输入边界的位置、运动、焦点、光线、声音与物体状态，写清下一事件和连接过程 |
| 白模 | 几何体承载路径、调度、运镜或照明中的明确职责；外观、材质和人物另锁，去掉坐标线和相机锥体 |

“@图作为参考首帧”不自动等于API首帧锁定；文字中的MOV、分辨率或某设备也不等于实际设置。封装格式本身不保证颜色/声音连续，需核对真实编码、色彩与声轨处理。

## 3. 参考素材最小充分

实际有几份引用几份，不填虚构编号。例：`@图片1锁定人物面部与服装；@图片2锁定客厅拓扑和主光来源；@视频1只参考动作节奏。` 一份素材可提供兼容属性，但不同素材不能争夺同一属性真源。

平台允许数量是上限，不是推荐目标；“1–8主体稳定、少于15镜稳定”等未记录对照结果不作为通用阈值。先用足够但少的素材；主体多、易混淆或关键接触难控制时再补独立清晰参考，不给每件背景物都建资产。

灯光附件先提取可见关系：哪盏灯、方向、软硬、主体/背景明暗、冷暖与材质。小字设备表和精密数值不能替代提示词中的关键描述；详见 `camera-light-quality-baseline.md`。

## 4. 针对执行器编译

完整提示词按 `output-contract-and-validation.md`，简单片段与局部编辑用相应短格式。本文件不另建竞争模板。

- 开场只说片型、媒介表达、整体调性和观众感受；具体剧情在分镜。
- 时间轴连续，整数秒方便读；关键动作写先后、接触和完成态，不用密集小数秒或高频次数假装逐帧控制。
- 分镜用自然句：明确主体、具体位置、准确动作、变化与结果。光影先写场景基线，局部变化贴近事件。
- 同一个形态变化可有连续几种形态，但必须共享清楚的身份与变化规则；现实接触与遮挡仍成立。减少同时竞争，不自动删掉创意。
- 情绪写触发与可见改变；手持抖动、延迟追拍、暗光噪点等按用户媒介保留，关键结果留可读时刻。
- 实际参数、必要数量/尺寸和准确原文保留；不默认给模型无定义的微小亮度/色彩百分比。

## 5. 实际失败后怎样改

先看失败片段，区分身份混淆、空间不可达、接触错误、动作过载、时间未读清、光源变化和压缩画质。锁定成功变量，优先改主因：明确起点和持有权、拉开动作先后、重设切点或局部机位；反复失败再升级关键帧、动作参考/白模或拆生成单元。

要研究“哪种写法更好”，用同任务、同素材、同入口与相同可控设置做少量对照，每次只改关键写法；记录原提示词、生成结果、漏动作/穿模/身份/光影/可读性，不凭单次好坏下全局结论。有随机种子且入口支持时固定；没有就承认随机性并在需要时复验。

本技能未因此自动执行视频实验；以后只有真实生成并观察到的结果才进入已验证经验。模型版本或入口变更时重查官方能力，不机械继承旧版本参数。
