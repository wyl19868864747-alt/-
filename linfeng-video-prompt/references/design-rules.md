## 1. 诊断优先级

按以下顺序排查，前项未解决时不要靠增加细节补救后项：

1. 第一轴是否正确：成片最终服务产品/品牌，还是人物关系/剧情。
2. 第二轴是否唯一：人物表演与关系因果主导，还是氛围、商品体验与视觉证据主导。
3. 全片氛围、色彩、主光、保护逻辑、成像和声音母规则是否先建立。
4. 模型任务是否正确：从零生成、参考、关键帧、白模、编辑、延长或转场。
5. TVC 的传播命题/产品证据或短剧的冲突/知情曲线是否唯一清楚。
6. 每镜为什么存在、观众当前知道/不知道什么、镜尾新增什么是否清楚。
7. 空间、人物/产品站位与单镜主任务是否明确。
8. 动作因果、运镜、物理、尺度与轴线是否连续。
9. 表演、光影、材质、声音和情绪是否服务主导层。
10. 输入/交付问题是否被误写成提示词问题，负面约束是否必要。

## 2. 图层式描述

“图层”是组织语言的方法，不是要求模型真的逐层渲染。建议顺序：

- 环境层：地点、时间、稳定空间骨架、远景。
- 结构层：墙、窗、门、道路、桌面等决定关系的实体。
- 主体层：人物或产品的位置、朝向、尺度。
- 动作层：当前动作及作用对象。
- 反应层：衣物、头发、道具、环境产生的合理反馈。
- 摄影层：景别、机位、镜头运动、焦点。

开场或换场时完整建立；同一空间的后续镜头只重申与当前动作有关的层级，避免反复重建全场。

## 3. 精确与精简

精确是提供可见信息，啰嗦是重复同一意图。

- 抽象：“前方大厦高处的固定锚点”。
- 具象：“画面右上方，玻璃幕墙第七层的竖向金属拼缝”。
- 重复：“只发射一次、禁止第二次、禁止两根、全片只有一根”。
- 精简：“右手向该拼缝发射唯一一根蛛丝；后续沿用，不再发射。”

优先使用名词、方位、动作结果和可量化关系。减少“高级感、炫酷、强烈、完美”等不能决定几何关系的形容词。

## 4. 镜头容量

降低单镜头同时变化的变量数量。以下变化通常应拆镜：

- 极近特写切换为全景空间。
- 固定等待切换为高速跟拍。
- 人物掠过摄影机后摄影机大幅转向。
- 连接物发射、绷紧、牵引和完整摆荡。
- 接触墙面、跑墙、脚部蓄力和跃离。

拆镜不是越碎越好。若动作在同一景别、同一轴线、同一速度关系下连续发生，可保持一镜完成。

拆镜前先读取 `director-information-control.md` 回答“这一镜为什么存在”。如果删除一个镜头后信息、关系、产品证据和观众感受完全不变，直接删除或合并，不因景别或运镜不同而保留。

## 5. 正向成片与后台禁令

先在后台用禁令识别风险，再把风险改写成模型应该生成的肯定式成片。用户只要主提示词时，禁令、理由、验收语言和导演自检不得进入提示词正文。只有用户明确要求独立负面提示词或平台具有独立负面栏时，才在主提示词之外输出一至三条可验证风险。

把“禁止向上、禁止斜向上、禁止漂浮、禁止滑墙”改成：“三步均沿同一楼层水平向前，脚底每一步都短暂压实墙面，身体重心随步伐向前推进，头部始终保持同一楼层高度。”

## 6. 常见故障及改写

| 故障 | 常见原因 | 改写策略 |
| --- | --- | --- |
| 人物突然闪进 | 未写入画路径或镜头首帧站位 | 写起点、入画边、由小到大的尺度变化 |
| 穿模 | 接触对象模糊；同镜变化过多 | 指定接触面和接触顺序；拆出接触特写 |
| 忽略后半动作 | 单镜头任务过载 | 只保留一个主动作，把结果作为切点 |
| 手别/道具数量变化 | 每镜重新描述，未继承状态 | 建立唯一道具并写镜尾/镜首状态接力 |
| 空间旋转 | 运镜与墙面动作竞争；地平线未锁定 | 采用侧后方平移跟拍；明确墙竖直、地平线水平 |
| 物理失真 | 缺少受力、支撑和惯性结果 | 写动作原因→接触→反作用→结果 |
| 画面没有氛围 | 只有限制，没有视觉主体 | 先写一段连续可视的电影画面，再精简约束 |
| 多次抽卡差异大 | 锚点、站位、镜头目的不稳定 | 固定首帧空间结构、人物方位和单一主任务 |
| 技术名词很多但画面无变化 | IMAX、UE5、Octane、VFX 等只作为口号堆叠 | 为每个词分配唯一职责并转译为可见结果；删除无贡献的词 |
| 文字很顺但脑中没有画面 | 主体、动词、路径或结果被抽象形容词取代 | 改写为当前状态→动作→接触/变化→可见结果 |
| 变形像突然换素材 | 只写“变成”，没有形变过程和身份继承 | 写原形如何拉伸/折叠/重组，并保留颜色、附件或轮廓锚点 |
| 运镜像无目的炫技 | 先写运镜，再临时安排主体 | 先让事件发生，摄影机因追随、观察或躲避而反应 |
| 人能看懂但模型漏动作 | 单镜时间、主体或高成本变化过多 | 保留意境，按不可逆结果拆镜；重新核对总时长与时码 |

## 7. 视觉技术词的使用边界

专业品牌词不能代替画面设计。先问它具体改变什么：画幅空间、动态范围、材质、间接光、反射折射、体积效果、合成可信度，还是美术方向。没有可见贡献就删除。详细选择与组合规则见 `visual-quality-stack.md`。

## 8. 人脑成像与模型容量

先做“人脑成像测试”：读一遍是否能连续看见主体、动作、变化和结果；再做“模型容量测试”：这些画面能否在给定时长、景别和单镜任务内完成。语言清楚是必要条件，不代表动作密度可以无限增加。详细写法见 `visual-language.md`。

## 9. 提示词层级

成品格式、开场概念边界、资产/情绪/空间分工与声音位置唯一见 `output-contract-and-validation.md`。信息压缩和复杂度判断见 `prompt-compilation-and-consistency.md`。本文件不另建模板；局部修改仍只改受影响内容。

## 10. 广告、剧情、UGC 与技术演示分流

不同任务不套同一结构：

- **TVC/产品广告**：先确定唯一传播命题和目标情绪，再设计视觉钩子或感官建立 → 产品自然进入 → 材质/功能/体验的可见证明 → 人物或环境反馈 → 英雄定格。每段只展示一个主要卖点；人物、场景、运镜和特效不能抢走产品焦点。
- **短频快电商 UGC**：前 1–3 秒用遮挡、反常状态、疑问动作或结果先行建立单一钩子；揭晓后立即用场景和口播证明用途，不写空泛夸赞。
- **剧情/对话**：故事因果、人物关系、轴线、表演节奏优先；光线服务情绪连续，不为了高级感每镜重新布光。
- **技术演示/前后对比**：先定义不变区、变化区、触发物和完成条件；视觉重点是状态变化清楚，不是氛围词。

广告追求高密度但不等于多动作；剧情追求表演不等于长篇心理说明；UGC 追求真实不等于降低画质；技术演示追求准确不等于堆禁令。

含卖点文字的广告先把文字当作空间图形元素设计，而不是把多条英文当普通字幕依次叠加。只保留少量辅助卖点，分别说明入场方向、停留区域、前后景层级、视差和退场；让其空间运动服务主传播命题。模型负责文字载体、光影和运动氛围，准确拼写、Logo、CTA 与法务文字交给后期替换，并提前保留安全区。若文案过多会造成乱码、漂移或拥挤，优先减少数量，不增加同义限制。

当历史、数据、年份或多个辅助卖点需要连续出现，且场景中存在合理实体载体时，先让信息沿同一载体逐步揭示，再设计其空间呈现。模型负责载体运动、透视、材质和光影，准确文字后期替换。只有一句核心口号或没有合理载体时保持直接表达，不为隐喻强加道具。本方法来自单一公开案例与风险分析，属于中低证据的条件工具；它补充而不替代卖点文字空间化。

对便利零售、饮料、零食、家居消耗品等高度同质化日常产品，可以先建立一个具体生活摩擦，再让产品通过最短真实动作解除摩擦，并由人物使用前后的身体节奏或关系状态变化证明价值。该方法目前为单一系列支持的低证据观察，只在对应品类条件启用；高技术、强功能对比和法规信息任务不使用。始终保留产品可读性、真实尺寸、功能证据、品牌识别和转化 CTA。

## 11. 摄影与光影

新写、完整重写和光影返修固定读取 `camera-light-quality-baseline.md`，建立场景基线并按其规则放进成品。摄影、灯光、色彩、材质、运动与合成只写当前任务有用的可见结果；分镜继承全局，补局部变化。

输入分辨率、编码、码率与平台压缩问题按 `visual-quality-diagnostics.md` 定位，不用设备词或“8K”替代真实交付设置。

## 12. 状态变量与失败后的改法

多镜、多时段或状态变化任务先按 `prompt-compilation-and-consistency.md` 建立最小时间轴状态账本并通过 `Consistency Gate`；本节状态表用于局部效果控制，不能替代全文一致性检查。

对“始终保持”“只改变局部”“光标划过后恢复”等任务，先建立状态表：

| 变量 | 开始状态 | 触发条件 | 结束状态 | 始终不变 |
| --- | --- | --- | --- | --- |
| 画面左侧 | 全域模糊 | 无 | 全域模糊 | 不被对比线影响 |
| 对比线右侧经过区 | 模糊 | 对比线扫过 | 清晰 | 未经过区仍模糊 |
| 新切镜头 | 全域模糊 | 光标再次进入 | 局部恢复清晰 | 不继承上一镜已清晰区域 |

模型多次泄漏状态时，不继续叠加“禁止变清晰”的同义句。改用固定首帧、遮罩式局部作用、硬切重建状态或减少同镜变化变量。失败修复优先改变结构，其次才增加禁令。

## 13. 局部修改原则

用户要求“只改左侧模糊”“换手”“精简这段”时：

1. 找出受影响的状态、镜头和承接关系。
2. 保留未涉及的开场总控、视觉母规则、资产锚点和成功段落。
3. 只重写相关字段；若改动会破坏连续性，连同前一镜镜尾或后一镜镜首做最小范围修补。
4. 压缩语言时不得删掉主体、路径、结果、光源或画质底线。

## 14. Agent 工作流交接

用于 CCPM 或多阶段 Agent 流程时，按“大纲 → 资产 → 分镜 → 视频提示词 → 生成检查 → 剪辑”传递，不让下游重新猜上游已确认内容。每次交接只带一个精简的“生成合约”：

- 目标：时长、画幅、平台、故事/广告目的。
- 资产：人物、产品、场景引用及各自职责。
- 母规则：空间、站位、身份、产品几何、摄影、主光、色彩和声音。
- 当前镜头：首帧状态、单一主动作、可见结果、承接状态。
- 验收：本镜最重要的成功条件和 1–3 个高风险错误。

上游只定义稳定约束，下游只扩写当前阶段所需细节。不得在每个 Agent 中完整重写同一套背景和禁令；新信息与生成合约冲突时，先保留已确认母规则并标记冲突。
