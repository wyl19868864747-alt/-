# 通用摄影、光影、成像与画质基线

## 1. 强制执行方式

每次新写、重写或进行技术调整，先在后台建立完整技术方案；编辑任务默认继承原片，延长任务从原片边界连续，除非用户明确要求重新设计摄影、光线、风格或画质。

同时完整读取 `spatial-optics-physics-control.md`。它负责首帧/镜尾状态、空间 Scene Graph、参考职责解耦、光学可见结果、Physical Causality Chain、Lighting Geometry 与跨镜状态继承；本文件负责摄影身份、成像、光影和画质总基线。两者互补，不重复堆叠。

### 开场总控与技术基线分权

直接视频提示词的 `【开场总控】` 只负责定义整片的**风格、调性、情绪观感、平台感、节奏气质，以及必要时的超现实程度**。它是概念级观看契约，不负责讲具体剧情、分镜安排、人物动作、产品Proof、镜头时码，也不在这里堆摄影机、镜头、渲染器或VFX名词。

开场总控优先压成1—2个高密度句。示例逻辑：`一支冷峻、高级、极简的超现实概念广告；现实材质与一个不可能但可信的事件并置，整体克制、神秘、具有奢侈品/时尚概念片的视觉张力。` 示例只说明抽象层级，不固化具体风格。

摄影身份、机型、光学、灯光、运动、渲染与合成先在后台完整选型，再压缩到结构化提示词第三部分的一句 `【全片视觉与技术基线】`；**分镜和可见动作始终占主要提示词带宽**。

当“用什么相机拍”会明显改变可信度、媒介身份或成像结果时，读取 `camera-identity-selection-engine.md`，先按大片/剧情/纪录/UGC/新闻/年代影像等选择摄影机家族，再转译为可见结果。不得为了显得高级，把所有真实生活内容默认升级成 ALEXA/VENICE；也不得把手机、MiniDV、ENG 与大画幅电影机的成像行为混在同一镜头。

后台方案必须完整，最终可复制提示词仍在第三部分使用一句：

```text
【全片视觉与技术基线】
[必要的摄影/成像身份]；[透视与主要运动质感]；[色彩语法与肤色/产品色保护]；[主光真实来源、世界方向、软硬与色温]；[关键材质与高光/暗部结果]；[必要的渲染/合成职责]。
```

这句话不是设备清单。设备、软件和工业级效果词只用于**精确框定成像上限**：先选一个主摄影身份；只有CG/VFX确实承担画面机制时，再选一个主渲染/合成语义。不得把 IMAX、ARRI、VENICE、RED、Unreal Engine 5、Octane、ILM、8K 等多个体系无差别堆叠。具体设备名只有在它会实质改变画面时才保留，并必须同时落到可见结果，例如真实光学景深、微距材质解析、受控高光、自然运动模糊、真实接触阴影或一致的实拍/VFX颗粒。

镜头段只写当前真实变化，如机位改变、拉焦对象、运动起止、曝光触发、特殊材质事件或VFX状态；不重复全片设备与画质基线。

## 2. 后台完整技术方案

逐项确定但默认不外显：

1. **摄影机身份与成像方式**：先判断专业电影组、纪录摄影、创作者本人、手机用户、新闻摄像或年代家用摄影，再选择手机原相机、数字电影机、胶片观感、MiniDV/早期数码磁带、ENG、纯CG、虚拟场景或实拍与VFX混合；需要具体机型时读取 `camera-identity-selection-engine.md`；
2. **透视与光学**：先按内容决定广角/自然透视/长焦观察等镜头性格，再用摄影机物理距离、主体比例、透视扩张或压缩、背景行为、景深和焦点策略描述可见结果；毫米数、FOV、镜头品牌与光圈只在确有控制价值时补充，不作为唯一控制；
3. **运动设计**：固定、手持、跟拍、Dolly、弧线、摇镜、拉焦等实际动作，触发、路径、速度与落幅；
4. **曝光运动**：帧率/快门观感、自然运动模糊、慢动作/速度坡度、曝光与白平衡行为；
5. **色彩语法**：主色、辅助色、唯一强调色、色彩来源与分段变化；
6. **光源几何**：主光真实来源、世界方向、高度、软硬、色温、距离与作用对象；同时明确摄影机位于光源哪一侧、主体哪一面处于阴影/轮廓光、背景亮度和曝光优先级；
7. **保护逻辑**：肤色、产品本色、暗部结构、高光层次、标签和文字载体怎样保持可读；
8. **材质解析**：皮肤、布料、玻璃、金属、液体、食品、包装和环境表面的关键行为；
9. **空间与首尾状态**：复杂镜头先建立最小 Scene Graph，并记录 First Frame State / End Frame State，锁定人物左右、前中后景、身体朝向、头部朝向、视线目标、关键接触关系、道具手别、地标距离和下一镜继承状态；
10. **动作物理因果**：复杂交互按 `Cause → Contact → Force → Movement → Inertia / Weight Transfer → Result` 检查，先有真实动作和接触，再发生门、车辆、产品、身体、液体、布料或环境变化；
11. **渲染/合成**：纯实拍写物理成像；CG/混合任务只选择当前需要的渲染、模拟、跟踪与合成职责；
12. **交付链**：高清生成、真实输出规格、码率、编码、平台二次压缩与后期超分需求。

需要设备/镜头/灯具/运动系统/渲染器细选时读取 `cinematography-toolkit.md`；出现IMAX、UE5、Octane或大型VFX时读取 `visual-quality-stack.md`。工具只用于后台选型，最终句优先写可见结果。

## 3. 氛围、色彩与主光连续

技术方案必须服从 `direction-routing.md` 中的母规则：

- 整片及必要分段的氛围曲线；
- 全片主色、辅助色、唯一强调色及承担对象；
- 主光真实来源、世界方向、软硬、色温与时间连续；
- 肤色、产品色、暗部与高光保护；
- 成像触感与声音触感。

摄影机绕到人物另一侧时，光在画面左右的位置可以改变，但世界主光方向不变。日夜、室内外或彩色光变化必须由时间、地点、灯具、遮挡、反射或曝光行为触发。

逆光、侧逆光、剪影等强方向性设计必须进一步锁定 `主光来源 → 世界方向 → 摄影机相对光源位置 → 主体阴影/轮廓状态 → 背景亮度 → 曝光优先级`。优先写目标画面，例如“摄影机始终在人物阴影侧，背景保持更亮，人物正面自然压暗，轮廓光勾边”，而不是先堆“不要平光、不要补光”等负面词。

### 3.1 高冲击 Hook 的色彩分离合同

当首屏依赖危险悬置、异常主体、视觉奇观或 `attention-first-hook` 获取停留时，先把“色彩有冲击力”拆成五个可见决定：

1. **主环境色**：用一个大面积统一色域迅速建立世界，不把多个高饱和颜色平均铺满；
2. **轮廓锚点色**：人物服装、关键道具或威胁主体使用深色、中性色或互补色，与环境形成一眼可读的轮廓；
3. **唯一强调色**：只交给最需要被记住的产品、品牌物件、危险信号或动作结果，不在镜头间无因换主；
4. **保护色**：肤色和产品本色不被氛围色完全污染，关键标签、面部和接触点保持可辨识；
5. **层次分离**：用水面光斑、窄轮廓光、渐变反射、明度差或冷暖差分开前中后景，同时保留通透暗部与不过曝高光。

提示词优先写成：`[主环境色与来源]形成统一世界；[轮廓锚点]与背景清楚分离；[唯一强调色及承担对象]集中注意力；[肤色/产品色]保持自然本色；[高光、暗部和前中后景]保持层次。` 不把某次成功案例的青蓝水体、黑衣或银色高光固化为所有 Hook 的默认配色。

## 4. 可见画质标准

将“高清、电影级、4K、8K”转成：

- 主体边缘稳定，不发糊，不出现数字过锐光边；
- 皮肤保留毛孔、细毛、局部油脂和真实漫反射；
- 布料织纹、玻璃折射、金属渐变反射、液体层次、食品湿润度与包装边缘真实；
- 高光平滑不过曝，暗部不发灰、不发脏、不出现大片压缩噪点；
- 动态画面保持自然运动模糊，不出现拖影、重影和果冻；
- 对焦稳定，曝光与白平衡只在真实触发下响应；若选择手机、DV、ENG或观察者摄影身份，可保留该媒介真实存在的轻微寻找焦点、曝光响应、自动白平衡或操作者迟滞；
- 色彩干净，肤色和产品本色不被氛围灯完全污染；
- CG/VFX与实拍共享透视、畸变、景深、颗粒、接触阴影、反射和互动光。

## 5. 任务基线选择

| 任务 | 成像与透视 | 光线与画质重点 |
| --- | --- | --- |
| 高定人物/香水/美妆 | 受控数字电影机或大画幅观感，中长焦/微距，克制景深 | 单一方向硬光或大柔光塑形；中性证明光保护肤色/产品色；皮肤、玻璃、液体与金属分离 |
| 写实剧情/对话 | 自然透视，中景/近景优先，景深足以保留关系 | 窗、门、灯具等场景光贯穿，肤色稳定，暗部开放，不为反打重新布光 |
| 产品英雄镜/材质微距 | 中长焦或微距，关键结构保持在焦平面 | 轮廓、渐变反射、折射/焦散与接触阴影；标签、几何和产品本色稳定；镜头停稳 |
| 原生手机UGC/商品体验 | 现代手机主摄，近距离真实透视，轻微手持/自动对焦/曝光行为 | 太阳、窗光、露营灯或室内实用光；干净真实肤质与材质；不用大画幅/CG词覆盖手机逻辑 |
| 高级创作者Vlog/小团队纪实 | 轻量Cinema Line/纪录电影机观感，全画幅或自然浅景深，手持可控 | 低照度与实用灯保留、自然肤色；允许轻微操作者呼吸和快速但非机械完美的对焦 |
| 年代Vlog/家庭录像/旧DV | 小传感器深景深、有限动态范围、伺服变焦与自动曝光/白平衡行为 | 高光较易溢出、轻微磁带/数码噪点、对焦寻找与曝光抽动必须低强度且有触发 |
| 高速动作 | 较深景深、稳定主轴和地平线，自然或明确慢动作 | 亮部不炸、暗部不糊，运动模糊方向真实，主体与背景不闪烁；高速横移/机械运动可优先全局快门类电影机 |
| CG/混合媒介 | 按主体尺度与环境选择物理透视 | 只选择一个主渲染路径；模拟与合成承担明确接触、反射、互动光和颗粒匹配 |

表中是后台方向，不是成品器材清单。焦段、光圈、景别、动作速度和景深必须相容；一镜到底默认使用同一物理镜头或明确连续变焦。

## 6. 画质问题路由

画质异常时读取 `visual-quality-diagnostics.md`，先定位唯一主层：输入素材、光影曝光、材质纹理、运动稳定、色彩后期或交付压缩。

任何参考生成先做输入分级：

- **A级**：清晰低压缩、曝光正常、关键材质/结构可读且有足够多角度；可做受控微距与中等复杂运动；
- **B级**：主体可读但轻度压缩、细节或角度有限；保持已知正面/三分之四角度，降低微距、高速和复杂结构展示；
- **C级**：模糊、重压缩、过曝/欠曝、帧间不稳或仅单一角度；先补资产，无法补充时使用固定/轻微镜头，不恢复不可见标签、侧背面、内部或材质细节。

- 输入模糊、单角度或低压缩质量时，降低微距、高速、360°和不可见结构展示；
- 下载为低码率720p或平台二次压缩时，检查高清模式、下载规格、码率、编码、发布链和超分；
- 不用“8K、超清、电影级”修复交付层问题。

## 7. Prompt 编译约束

复杂镜头先在后台按以下顺序建立控制，再压缩为用户要求的成品提示词：

`Scene Context → Active References → Spatial Map → First Frame → Spatial Blocking → Optical Outcome → Camera Behavior → Action Timing → Physical Causality → Lighting Geometry → Audio → End Frame / Continuity`

最终不强制显示这些标题。优先保留身份锚点、首帧、空间关系、视线、接触位置、动作路径、镜头可见结果、光线几何、对白与跨镜状态；删除参考图已经稳定提供的冗余外貌描述、无职责设备参数和泛化审美形容词。

局部失败优先用一条正向状态锁解决，例如：人物第一帧已经在位、身体朝向与视线分别锁定、手保持接触直到动作完成、摄影机保持在阴影侧、长焦背景压缩持续不漂移。只有高概率严重错误反复出现时，再增加最少量局部负向约束，不建立巨型通用 Negative Prompt。

## 8. 输出前检查

- `【开场总控】` 是否只定义整片风格、调性、观感、平台感、节奏气质与必要的超现实程度，而没有提前讲具体剧情、分镜、产品动作或设备清单；
- 摄影机身份是否与摄影者、片型、机位、稳定度、对焦、曝光和年代一致；
- 是否先完成后台完整技术方案，再压缩成一句第三部分基线；
- 技术基线是否固定为成品第三部分；
- 句子是否同时覆盖必要摄影身份、成像/透视、运动、色彩、光源几何、材质和必要合成；
- 是否只保留一个主摄影身份，并在需要CG/VFX时只增加一个职责明确的主渲染/合成语义；
- 是否把具体设备/引擎名转译成了可见结果，而不是用名词堆叠替代画面设计；
- 复杂镜头是否建立了 First Frame State / End Frame State 与最小 Scene Graph；
- 身体朝向、头部朝向、视线目标、手别、接触点和地标距离是否分别明确；
- 参考图是否按 Identity / Location / Prop-Product / Vehicle / Style 分权，避免互相覆盖；
- 光学控制是否优先落到摄影机物理距离、透视、压缩/扩张、背景和景深等可见结果；
- 复杂动作是否满足 Cause → Contact → Force → Movement → Inertia / Weight Transfer → Result；
- 光线是否明确真实来源、世界方向、摄影机相对位置、阴影/轮廓状态与曝光优先级；
- 是否删除无职责的设备、软件和渲染器堆叠；
- 镜头段是否只写变化项，没有重复全片基线；
- 可见画质是否落实到边缘、皮肤、布料、玻璃、金属、液体、高光、暗部、运动、焦点和颜色；
- 输入/交付问题是否已在正确层解决。
