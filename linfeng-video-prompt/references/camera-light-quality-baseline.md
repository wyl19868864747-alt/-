# 摄影机与成像基线｜Always-on Capture Baseline + Conditional Lighting Design

## 0. 权限与调用

本模块拆成两层：

1. **Capture Baseline｜常驻层**：任何新写 / 重写视频 Prompt 都必须读取并在后台执行。它负责摄影机行为与成像底盘，不能因为用户没有主动说“画质、摄影、灯光”而跳过。
2. **Lighting / Advanced Cinematography｜条件层**：只有光线、材质、摄影方案本身决定结果，或用户明确要求 / 当前成片正在返修这些问题时才展开。

“常驻”不等于把整套摄影术语写进每个镜头。默认只把一条最短全局成像基线编入 Prompt；逐镜只有出现明确风险或视觉职责时才补局部可见结果。

用户明确要求低清监控、DV、旧手机、故意失焦、强噪点、过曝实验影像等媒介时，以用户媒介为准，不强行修成干净数字电影画面。

默认篇幅权重仍低于：
`主体/产品 > 事件 > 动作/状态 > 连续性 > 每镜简短摄影机`

## 1. Capture Baseline｜每次必过

后台每次检查以下六项，但最终 Prompt 不机械逐项列出。

### 1.1 摄影机是现实中的观察者
- 景别、机位和运镜必须能由真实摄影机完成；
- 摄影机运动与人物动作、视线、遮挡、形变或空间揭示耦合；
- 横移 / 前后移动存在真实前中后景视差，不像平面贴图；
- 快速主体或快速镜头运动保留与速度相符的自然运动模糊，不做冻结锐边；
- 镜头停止或主体急停后允许轻微自然收稳，不做无惯性的“游戏自由摄像机”；
- 焦点和景深服务当前信息层级，不把“电影感”机械等同于全片大光圈浅景深。

### 1.2 成像底盘
默认追求：
- 主体关键细节清楚、解析度充足，但边缘不过锐、不出现数码锐化白边；
- 皮肤保留毛孔、油脂与局部色差，布料、金属、玻璃、塑料等材质保留真实表面结构；
- 材质必须有与光源方向一致的反射、折射、漫反射或透光反馈，不统一成塑料亮面；
- 最亮区域仍保留层次，不无因死白；暗部保留结构，不无因死黑或脏灰；
- 人物、产品与环境处于同一受光世界，光源方向不随切镜无因换侧；
- 运动区域允许真实运动模糊，静止关键主体保持可读，不用“全画面刀锐”冒充高清。

### 1.3 默认全局编译句
普通写实视频可压成一条：

`真实摄影透视与自然运动模糊；主体细节清楚但不过锐，皮肤与关键材质保留真实纹理和受光反馈；亮部保留细节、暗部保留结构，景深随当前信息层级自然变化。`

这是一条**可改写的功能句，不是固定咒语**。如果用户媒介是手机 UGC、家庭录像、胶片、监控等，要按媒介改写，而不是原样复制。

例如手机 UGC：
`手机主摄真实曝光与轻微手持，快速动作保留自然运动模糊；人物和产品细节清楚但不过锐，背景景深不过度虚化。`

如果这些结果已经由用户参考图 / 参考视频或明确媒介完整锁定，可进一步压短，但后台检查不能省略。

## 2. Shot Camera｜每镜仍然必须执行

常驻成像基线不替代每镜摄影机描述。

每个明确镜头仍按主 Skill 写：
`景别 + 观察方位/机位 + 一条短运镜`

并满足：
- 运动有事件触发；
- 镜头结束后新增可见信息，或让关键过程持续可读；
- 固定机位用于需要连续观察的过程，不为了“丰富”强行移动；
- 相机速度与主体动作匹配，不在普通动作中突然无因高速甩动。

复杂动作摄影、一镜到底、强注意力调度继续读取 `director-camera-attention.md`；具体焦段 / 光学方案继续读取 `cinematography-toolkit.md`。

---

## 3. 局部可见结果｜按风险选，不做套餐

只有当前镜头确实有风险时，补最短的一条或两条。

### 快速移动容易“AI锐边”
`转身和横移边缘保留自然运动模糊，停下后主体重新稳定清楚。`

### 横移像贴图
`前景掠过速度明显快于远景，形成真实空间视差。`

### 焦点层级混乱
`当前说话者和手中产品保持清楚，远背景自然退焦。`

### 皮肤蜡感
`皮肤保留轻微毛孔、油脂与局部色差，不磨成均匀蜡面。`

### 玻璃 / 金属容易假
`玻璃边缘保持透明折射，高光不过曝；金属反射沿表面曲率连续变化。`

### 产品 / 人物漂浮
`承载面保留自然接触关系与轻微接触阴影，主体不悬浮。`

### 暗部死黑 / 脏灰
`阴影面保留少量环境反射和结构，不抬成均匀灰雾。`

## 4. Lighting Design｜条件层

复杂灯光设计仍然**按需启用**，不因为 Capture Baseline 常驻就强制展开。

命中以下任一情况时才重点写光：
- 光线直接决定主体是否可读；
- 产品材质、颜色或卖点依赖受光；
- 光线本身触发剧情或状态变化；
- 当前成片问题就是过曝、死黑、脏灰、塑料感、环境脱节；
- 多场景存在明确不同的光源逻辑；
- 用户明确要求摄影、灯光或画质方案。

需要写光时，先回答“光从哪里来”。

光源可以来自窗户、顶灯、屏幕、火焰、霓虹、车灯、发光产品等；环境色只影响合理受光面。相机换侧时，光源在世界中的位置不跟着摄影机一起换边。

普通片不独立建立长篇【光影】块；能并入相关镜头就并入。只有多场景灯光明显不同、产品材质展示依赖精确布光、光线驱动剧情或用户明确要求摄影方案时，才展开独立灯光段。

## 5. 设备与光学名词

设备名不是质量咒语。

只有用户明确指定，或设备身份会直接改变可见结果时才保留，例如：
- 手机主摄：自然曝光变化、轻微手持、有限暗光表现；
- 数字电影摄影：柔和亮部、自然肤色、受控景深；
- 大画幅胶片：更明显的空间尺度、细微颗粒和柔和亮部。

不把 IMAX、ARRI、UE5、Octane、ILM、8K、HDR 叠成通用“高级套餐”。

焦段、光圈、色温只有在数值本身会改变结果或用户明确要求时写；优先转换成可见效果：
- `近机位广角，前景明显放大，背景快速退远。`
- `远机位长焦，主体尺寸保持稳定，远景在身后显得更近。`

不输出无测量依据的假精确值。

## 6. Prompt Pollution Audit

写入摄影 / 成像 / 光影句前检查：

1. 这是常驻成像底盘，还是专项灯光设计？
2. 全局一句已经覆盖的结果，是否又在每镜重复？
3. 局部句是否解决一个明确风险或承担一个视觉职责？
4. 是否只是设备名、摄影术语或“高级感”包装？
5. 是否开始比主体、动作或产品描述更长？
6. 是否与用户明确媒介冲突，例如把手机 UGC 强行修成无噪电影摄影？
7. 是否为了“清晰”错误删除了真实运动模糊、景深层级或材质细节？

最终原则：

> **摄影机执行和成像底盘每次都过；复杂灯光和高级摄影按需展开。让 Skill 懂完整摄影，让模型只看到最少、最有效的可见结果。**
