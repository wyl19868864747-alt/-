# 光影与成像：固定调用入口

## 何时使用与优先级

新写、完整重写和光影/质感返修时先读本模块；局部非光影编辑继承现有基线。光影是每次设计的明确步骤，优先于设备堆词和装饰，服从用户媒介、人物/商品事实、空间因果、叙事与关键证据。

## 先做一套看得见的光

按“场景＋时间＋主要灯光状态”定一套基线。只换景别、人物表情或机位，不新建方案；进入新环境、日夜转换、开关主灯或异常事件改变照明时才另定状态。先在后台确定下列关系，再压成几句必要信息，不照抄整张工程卡。

| 要确定什么 | 交给模型的具体写法 |
|---|---|
| 摄影/成像媒介 | 选一个主身份，如手机主摄、数字电影摄影、大画幅胶片、粗糙二维手绘或CG；说明它带来的透视、景深、运动与纹理 |
| 主光来源与位置 | 光来自哪扇窗/哪盏灯/哪个发光物，在世界中的哪一侧、什么高度；照到主体哪一面 |
| 光线软硬 | 直射日光形成清楚影缘；窗帘散射光让脸颊明暗柔和过渡；按场景选一种主关系 |
| 明暗层次与辅光 | 脸、手、商品证据谁需要读清；另一侧靠什么反射抬起，背景相对更暗还是更亮；阴影保留什么关键结构 |
| 色彩与材质 | 环境冷暖、肤色/商品本色、强调色归属；金属反射光源形状，布料保留褶皱，皮肤有自然层次，高光怎样过渡 |
| 状态与变化 | 主光固定在哪，移动后受光怎样改变；特效/屏幕/开关灯触发什么局部互动光，何时衰减或恢复 |

把空间锚点与光源连起来：优先“床旁的窗”“沙发后壁灯”，避免只写“左侧”而不说世界左侧还是当前画面左侧。相机换侧时可见亮面改变，光源仍留在原处。人物、商品、场景、反射和接触阴影共享同一光源逻辑。

## 设备名怎样保留

设备或软件标签可以帮助定位风格，配一条可见结果才有用。**媒介/设备概括可用一句，实际光源、明暗与材质另用短句；整个光影块不强塞成一句。** 不需要型号时直接写成像效果。

| 用户说法 | 应当落到的画面；只在相关任务选用 |
|---|---|
| 模拟IMAX胶片摄影 | 大画幅胶片观感，远景尺度清晰、亮部柔和过渡、细微颗粒；光线仍由当前场景决定 |
| ARRI Alexa＋Cooke | 数字电影摄影与柔和光学观感，肤色有层次、焦内主体清楚、背景柔和；不是设备名自动保证画质 |
| Unreal Engine 5 | CG环境/场景渲染职责，交代间接光、接触阴影与环境反射怎样统一 |
| Octane | 物理渲染器，不称“物理引擎”；用于需要可信玻璃、金属、透射和反射的CG材质描述 |
| 工业光魔级VFX | 合成目标：特效与实景在受光、遮挡、接触、运动模糊与颗粒上匹配；不是实际制作团队或工具开关 |
| 电影级东方奇幻 | 先确定人物、建筑、服饰与奇观的文化和美术细节，再定山雾层次、日光/月光、发光法器的互动光等具体关系 |

选一个主摄影身份；混合实拍与动画时明确各层媒介。只有CG/VFX承担当前画面机制，才增加对应职责，不把IMAX、UE5、Octane、ILM全列为通用质量套餐。器材、软件和“8K”风格词不等于真实调用了设备、渲染器或分辨率设置。

## 数值怎么处理

- 时长、画幅、人数、物品数量、已确认尺寸、准确文字和平台实际参数按需要保留。
- 摄影焦段/光圈、色温可作必要辅助；同时写明目标透视、景深和冷暖效果。光源色温与相机白平衡分开，不能用一个4500K同时代表两者。
- 不默认输出无测量定义的饱和度百分比、空气颗粒占比、肤色IRE、阴影EV等假精确值。用户工程表中的必要参数可留在制作方案，生成提示词先转成相对明暗和可见色彩。
- 不承诺Seedance或其他模型会精确执行数值、品牌设备名、时间戳或图卡上的小字。可测试的控制与写作经验分开，效果以实际生成复盘为准。

## 快速选用的成像方向

从当前任务选择，不叠加所有行，也不固定为每个项目的默认色调。

| 场景目标 | 可直接改写的基线 |
|---|---|
| 暖灯夜间关系戏 | 数字电影摄影观感，肤色自然、焦内面部清楚。沙发后暖色台灯形成柔和侧光，墙面微弱反射保留暗侧眼睛，窗外少量冷光分开轮廓；背景较暗，灯罩高光柔和收住。 |
| 白天窗边生活感 | 自然摄影质感。窗外日光经薄帘从床侧照入，脸与被褥柔和受光，背窗一侧靠浅墙反射保留层次；肤色中性温暖，白色布料纹理可见。 |
| 手机暗光随拍 | 手机主摄、手持追拍，保留暗光噪点和有触发的对焦/曝光迟疑。台灯与屏幕各照亮附近区域，房间深处自然偏暗；关键接触与最终结果仍能看清。 |
| 实拍＋发光手绘 | 实景沿用房间原光，手绘保留粉笔颗粒与逐帧轮廓抖动。发光线条仅轻微映亮邻近指尖/物面，随真实物体正确遮挡；房间物品保留实拍材质。 |
| 商品棚拍 | 产品摄影质感，真实结构与颜色清楚。大面积柔光从前侧照出主轮廓，窄条反射勾出金属/玻璃边缘；标签面可读，支撑面有接触阴影。 |
| 东方奇幻实拍合成 | 大画幅电影观感，山体远近分层，服装和建筑材质可信。选定日光或月光作为环境主光；法器发光时才映亮相邻手掌与衣袖，亮度随事件衰减，合成阴影与颗粒统一。 |

体积光需要有方向的光束与适量空气介质，不给每个室内自动加浓雾。轮廓光、补光与发光特效都有场景或布光依据；允许用户明确要求剪影、硬光、深暗部、颗粒、粗糙录像和非写实配色。

## 灯光参考与检查

优先从参考图提取主光、明暗和色彩关系，在文字中写出最关键的几项；“完全遵照附件全部数值”不作为唯一控制。没有图片不虚构引用。需要跨镜稳定、现有文字反复失效时，再建议相同场景和灯光状态的清晰参考图，不强制每个项目先做光卡。

交付前检查：主光是否可定位；镜头能否读清当前主任务；脸/商品颜色是否有依据；阴影、反射与材质是否一致；机位换侧和开关灯是否有正确状态继承；设备词删掉后是否仍能画出目标光影。

## 视频中的摆放位置

全片【光影与成像基线】放在【空间与场面调度】之后、【分镜描述】之前。通常先一句媒介/设备与可见质感，再用少量自然句写当前场景光源、层次与颜色；多场景按名称列出各自基线，不逐镜重抄。

镜头内只补变化项或当前主任务必需的局部光：通常接在**受影响主体/动作的描述之后，镜尾完成态或声音之前**。若光线变化是人物反应的原因，按发生顺序先写光，再写反应。没有变化且不影响理解就继承全局，不为每镜硬加一句光影。

例：`她走到窗边停下，抬手拉开薄帘。直射日光随帘缝展开，在手背与脸颊形成一条明亮光带；她眯起眼，停在半明半暗的位置。只听窗帘摩擦声。`

多镜的人物表演、动作与构图按各自段落展开；拍摄型号不用跟在每个景别后重复。主光方向、表演反应与镜头时间共同检查，不把三者写成互不相干的清单。


## 继续深入的条件

需要具体摄影家族读 `camera-identity-selection-engine.md`；细化光学读 `cinematography-toolkit.md`；高规格成像与合成读 `visual-quality-stack.md`；复杂世界方位读 `spatial-optics-physics-control.md`；输入/编码/压缩问题读 `visual-quality-diagnostics.md`。这些是条件模块，不因本入口被调用而全部加载。

强Hook的颜色仍服务主次：一个环境色系、一个主注意对象、必要强调色；轮廓与背景分离，肤色/商品色有保护，前中后景有明暗层次。不把青橙、暗调或某次成功案例配色变成通用套餐。
