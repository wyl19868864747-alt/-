# 提示词编译与一致性｜High-Signal Video Compiler

本文件负责把导演判断压成模型真正需要的执行语言。最终格式归 `output-contract-and-validation.md`；任何新写／重写视频 Prompt 都必须读取 `camera-light-quality-baseline.md` 并执行其中的常驻 Capture Baseline，复杂灯光与高级摄影仍按任务条件展开。

## 1. 核心原则

视频Prompt不是制作说明书，而是**时间中的可见事件**。

默认优先级：
`主体/产品、事件、动作及必要空间关系 > 景别/机位/短运镜 > 常驻成像基线/必要声音/真实性 > 专项光影与高级摄影 > 技术术语`

这是输出篇幅优先级，不是执行顺序；逐镜执行顺序统一由第5节定义。

用户本轮若明确要求灯光、材质、摄影或画质返修，对应层级可以上调。

任何一句如果删掉后，主体、事件、动作、空间、镜头、材质、光色、时间、文字或声音都不变，就删除。

## 2. Global Once, Shot Specific

全局信息只定义一次：
- 片型/媒介/调性
- 人物、产品、空间真源
- 一条按媒介改写的常驻成像基线
- 只有确实影响结果时才保留的专项主光/色彩基线
- 持续声音规则

分镜写当前变化及理解动作必需的继承关系；身份、外观和固定拓扑不重复介绍。未变化不等于可删除：“仍咬着黄鸭”若决定本镜拉扯关系，就必须留在本镜。

去重针对重复介绍，不删除当前动作依赖的空间信号；不把人物站位、道具位置或相机轴侧集中放在Prompt末尾。

## 3. Creative Preservation Gate｜先保护主记忆点

写 Prompt 前先用一句后台判断锁定本段 **Hero Idea / 主记忆点**：它可以来自事件、镜头关系、空间揭示、表演、产品证据、声音或构图，不要求一定是大运镜或视觉奇观。

执行顺序固定：

`先设计最值得看的可见瞬间 → 再检查事实/素材/时长/空间/物理/模型边界 → 优先修实现 → 最后才考虑降低创意幅度`

发现执行风险时，按以下顺序修：
1. 调整人物/物体路径、摄影机起终点或观察侧；
2. 改变切点、遮挡方式、镜头长度或动作先后；
3. 拆成相邻两镜或用可读中性机位重新建立空间；
4. 用参考图/关键帧/多角度资产补足输入证据；
5. 只有以上仍无法成立，才最小幅度降级 Hero Idea。

不得把“存在风险”直接等同于“改成固定中景/普通慢推”。但也不能反向强迫每条视频加入甩镜、环绕、极端透视或奇观；安静表演、稳定构图、一个准确的产品证明同样可以是 Hero Idea。

硬边界优先于创意保护：事实与合规、用户明确要求、已知模型能力、真实时长容量、素材证据、物理因果无法成立时必须收敛。收敛时保留原设计的核心信息效果，例如原本通过“甩镜＋遮挡揭示”制造突然发现，若高速甩镜不可执行，可改为更短横移＋完整遮挡揭示，而不是直接删掉揭示关系。

压缩阶段检查：如果最终 Prompt 相比批准/已确定的设计，只剩通用“中景、慢推、产品特写”，而主记忆点的触发、变化或落幅被删掉，判为 **creative erosion**，返回重编。

## 4. 保留用户强表达，但抽象目标先转译

用户已经给出有效的事件、动作或镜头概念时，优先保留原意，不为了“专业”机械展开。

例如：
- `她看到价格后愣住，再看一眼。`
- `真实场景突然被产品接管。`
- `镜头后拉，发现刚才的真实场景其实是一张图片。`

这些本身已经是高信号。只有为了因果、连续性或高风险错误才补必要细节。

最终模型指令不能出现结果评价词，不只过滤某张禁词表。逐句判断：这句话描述能拍到/听到的内容，还是希望观众产生的效果？后者先转译再删除；标题、总控、声音同样适用。

| 后台目标（不下发） | 编译成具体设计 |
|---|---|
| 前3秒抓眼 | 从动作中进入：幼犬前爪刚搭上缸沿，画外手拿来浴巾，它立刻把爪子收回；用实际动作与反差开场 |
| 信息推进快 | 删除重复揉洗、重复反应，每镜引入取瓶、上洗液、起泡、冲净中的一个新变化 |
| 可爱、舒服 | 幼犬下巴压低、眼睛半闭，身体向按摩的手掌靠近 |
| 有感染力的推荐 | 短句连说，在关键词重读；画面同步给对应操作证据 |
| 音乐突出情绪 | 追躲时短促木琴与轻鼓点，停手时鼓点抽空，放松后拨弦进入 |

“泡沫被冲掉、湿毛贴服、杯底落桌”是可见物理完成态，必须保留。禁止的是传播效果、观众反应、审美评价和内部创作目的，不是动作的因果终点。固定对白或产品名原文不当作导演指令做关键词误删；事实是否获准另行核对。

## 5. Per-Shot Spatial State Compile｜逐镜执行

每个新分镜编译前，后台先执行 `spatial-handoff-lock.md`：从上一镜结束时回答六问——主体在哪里；朝哪边；关键道具在哪、由谁持有/接触；目标在哪；摄影机在轴线哪侧、从哪看；动作最后进行到什么状态——再额外明确本镜谁移动、谁必须原地。首镜从已锁事实/实际首帧初始化，后镜不得重新建立一套空间。

执行链：
`事实/首帧 → 上一镜全员完成态 → 运动所有权（谁动/谁原地） → 继承人物/道具/朝向/接触与目标 → 当前关系及必要位移/转身 → 高风险移动段观察走廊 → 到达后的同地锚点/必要光向 → 能看清动作的新观察位置 → 景别/机位与空间层次 → 动作句与短运镜 → 当前全员完成态 → 下一镜`

先检验动作如何从既有位置发生，再据此选择相机位置；景别和运镜不能反过来迫使人物或道具瞬移。跨区域、往返或一动一静的高风险段，优先固定同一世界观察方向，让距离变化在画面中可见；角色抵达新地点后切近景，保留一个同地地标、前景遮挡或受光方向，避免位置复位。每镜再做一次极短的空间层次判断：如果真实场景本来就有靠近摄影机的门框、肩背、柱体、植物、家具、车辆、布料等，而且它能帮助空间展开或信息揭示，就让摄影机的横移、短弧移、跟拍或推进带出自然视差；在大场景变化时，可让近景短暂遮住部分画面，再随着遮挡边缘移开揭示新空间，并在主体和环境可读处减速收稳。前景必须有真实来源且不抢关键动作、表情、产品证据或文字；没有合适来源就不用。最终只把必要关系写进该分镜正文的一小段，不另建构图说明块。完成态可以是“正在向门口跑”，不强制镜尾停住。关键交互保留接近、接触、响应、完成态；动作装不进时间窗就拆镜或重排。

### Spatial Minimum Signal

每镜只输出影响生成的：`当前位置 + 朝向/运动方向 + 关键相对/接触关系 + 摄影机观察方向 + 必要继承状态`。无关项省略，景别与一条短摄影机状态仍按原规则保留；不输出状态表、房间平面图或“End-State”标签。

例如：`幼犬仍坐在浴缸中央，主人双手停在它肩侧；正面偏右中近景极慢前推。`

多主体连接要在同一镜里写完整关系，而非另附空间限制：`幼犬已绕到机器人前方，仍咬住卡在前缘的黄鸭，面朝机器人连续后退；机器人沿原路缓慢前进，黄鸭在两者之间绷紧。靠窗侧面全景轻微后移，保留嘴、黄鸭与前缘同框。` 具体左右从实际继承状态推导，不能把例句当固定站位。

### End-State Handoff

每镜后台生成**全员完成态**，下一镜以它为起始态；完整账本字段与物理变化规则见 `continuity.md`，运动所有权与固定观察走廊见 `spatial-handoff-lock.md`。未入画对象仍保留状态；没有明确起步/路径的角色继续原地，不能因主角移动或为了同框自动跟随。并行运动只能沿已经建立的路径、方向和已过时间合理推进，不借画外过程省略关键掉落、转向或交接。

摄影机也是空间状态的一部分：逐对比较上一镜**末位**与下一镜**首位**，同侧真实观察角变化大于30°，且新机位看得见所写接触/遮挡关系。组接详则归 `director-information-control.md`。需要证明狗—黄鸭—机器人仍连接时，先选能看见三者的侧前/侧面视点，不能以只见狗脸的特写代替证明。

空间变化缺因果、观察方向翻转、配角被无因带跑、或到达后近景失去所有同地证据时，重写该镜动作/机位；若需在前镜补动作，一起重算其完成态并向后复核，直到状态接回。禁止在Prompt尾部增加“空间位置锁/不得瞬移”等补丁。

## 6. 表演压缩

情绪优先转成短动作链，不默认展开面部肌肉清单：
- 震惊：`停住 → 核对 → 抬头`
- 怀疑：`盯住证据 → 迟疑 → 再确认`
- 紧张：`动作变小 → 呼吸收紧 → 视线快速确认出口`
- 松弛：`肩膀放下 → 呼吸变慢 → 轻笑`

只有面部特写、表演为主任务或用户要求FACS时，读取面部表情库展开。

## 7. 镜头与信息预算

每个明确镜头包含景别、观察方位与一条短运镜，快切子镜也不漏。直接写“侧面中景横跟，幼犬沿缸边挪步”，不先列全片摄影清单。若本镜的空间层次会实际改变观看结果，就把前景、视差、遮挡或揭示压进同一句动作—摄影描述；不要另起“构图”“前景”字段，也不要为了形式变化给普通镜头硬塞遮挡。剪辑约定归 `director-information-control.md`；叙事镜头常用极慢前推，不为形式差异强加大运镜。

篇幅先给人物/产品、事件、动作、空间接续。常驻成像基线全局只写一次并保持最短；声音、专项光影、设备等修饰默认短于主体与动作叙述，不在每镜重复画质套餐。参考能锁定的身份不重写小传；音色每位一句，阶段语气并入对白。

按以下顺序压缩：删效果评价 → 删重复清单 → 删次要修饰 → 合并同义指令。不能删核心动作、接触因果、机位、声音身份和必要事实来凑字数；**也不能把承担 Hero Idea 的触发、镜头关系、变化机制或落幅当成“复杂信息”误删。**

## 8. 真实性补丁｜默认最多1条

常驻 Capture Baseline 已负责基本摄影透视、运动模糊、清晰度层级与材质成像底盘；本节只处理当前镜头额外暴露的一个具体 AI 风险，不用来替代常驻基线。

完成主体、事件和镜头编译后，再判断：

`当前镜头最可能出现的一个AI错误是什么？`

只有答案明确，才加入一条最短的可见修正；没有明显风险就不加。空间断裂不走此补丁通道，返回第5节重编对应镜头；必要接触与状态因果不受补丁条数限制。

示例：
- 漂浮：`鞋底紧贴地面，保留轻微接触阴影。`
- 比例漂移：`产品尺寸和包装结构在推进中保持稳定。`
- 玻璃塑料感：`玻璃边缘保持透明折射，高光不过曝成死白。`
- 横移像贴图：`近景移动快于远景，形成自然空间视差。`
- 焦点混乱：`眼睛清晰，背景自然退焦。`
- 环境脱节：`火光只轻微影响人物朝向火源的一侧。`

不要把接触阴影、反弹光、高光滚降、景深、材质、空气透视、运动模糊全部列成固定套餐。

## 9. 摄影机与成像基线｜常驻；复杂光影按需

每次写／重写视频 Prompt 都必须执行 `camera-light-quality-baseline.md`：

### 9.1 常驻 Capture Baseline
后台固定检查：
- 摄影机运动可由真实摄影机完成，并与事件耦合；
- 横移／推进存在真实视差，快速运动有与速度相符的自然运动模糊，停止后自然收稳；
- 主体关键细节清楚但不过锐，静止信息保持可读；
- 皮肤与关键材质保留真实纹理和受光反馈；
- 亮部保留细节、暗部保留结构；
- 景深和焦点服务当前信息层级；
- 人物、产品与环境处于同一受光世界。

最终默认压成**一条全局成像句**，按手机、数字电影、家庭录像、胶片、监控等实际媒介改写；不在每个分镜重复。

### 9.2 条件 Lighting / Advanced Layer
以下情况才展开专项光影／设备／光学：
- 光线直接影响主体可读性；
- 材质或产品卖点依赖受光；
- 光线触发剧情或状态变化；
- 当前失败点是过曝、死黑、脏灰、塑料感、焦点／景深异常；
- 用户明确要求摄影、灯光、设备或光学方案。

普通镜头不建立长篇【光影】块。局部风险优先写一条可见结果，不列摄影术语套餐。

设备名只在能带来明确可见结果时出现。不把 IMAX、ARRI、UE5、Octane、VFX、8K、HDR 叠成通用高级词包。

用户明确要求低清监控、旧手机、DV、故意失焦或其他实验媒介时，媒介事实高于默认干净成像，不得用“画质基线”把设计修回无噪数字电影。

## 10. 复杂度决定长度

### 简单片段
单场景、单主体、一个主动作：一段或几句即可。

### 中等片段
多Beat、少量人物关系：总控 + 锁定 + 时间轴 + 必要声音/限制。

### 高控制片段
多人换位、复杂空间、产品连续、一镜到底、多场景光线切换、长片生产：后台展开所需状态，前台把必要关系并入相应分镜；用户要导演方案时可另展示分析，不将空间管理块下发模型。

**不是时长越长Prompt就必须越长；控制难度增加才增加文字。**

## 11. 最小状态账本

按第5节逐镜调用 `continuity.md` 的状态接力，不等全文写完再补账本。人物认知、焦点、必要主光与声音按任务附加到空间完成态。

下一段从上一完成态继续；没有变化也要保留当前动作依赖的最小关系。不可逆/阶段变化不能无因倒退：已湿→起泡→冲净→擦干不能重新回到首次打湿；冲净后不凭空再生泡沫；刚包浴巾不立即变全干蓬松。

用户给定首帧已处于中途，就从中途继续；若还需展示前序，明确设计回溯或先征得修改首帧的依据，不能静默重置。只有有意非线性叙事才标回溯，不用回溯为粗心错误补借口。

有对白时按 `voiceover-control.md` 逐时间窗核算；每镜可只有一个变化，介绍可覆盖多个镜头。先减重复信息和动作，再处理超时；不能让“镜头更密”变成“每镜塞更多动作”。

## 12. 冲突与污染检查

直接修正：
- 同时固定与环绕、同时前推与后拉等互斥镜头；
- 双手被占却执行第三个手部动作；
- 人物未到达却完成接触；
- 产品无因换款、换手、变大；
- 灯光无因随镜头换侧；
- 对结果提前反应；
- 精确对白重复出现；
- 同一个风格/质感词在多个分镜重复。

Prompt Pollution Audit：
1. 这句话是否直接影响视频结果？
2. 是否已在全局定义？
3. 是否只是解释一个模型已经懂的概念？
4. 是否只是为了显得专业？
5. 是否把可自由完成的实现锁得过细？
6. 常驻成像基线是否被错误省略，或反过来被逐镜重复成画质套餐？
7. 专项光影/真实性描述是否开始比主体和事件更长？
8. 是否仍把抽象创意判断词直接丢给生成模型？
9. 是否因为“更稳”把原本有明确职责的 Hero Idea 无依据改成通用安全镜头？
10. 是否反过来为了“创意”强塞与任务无关的甩镜、环绕、奇观或极端构图？

命中重复、解释性、低价值内容就删。

最终目标：**让Skill懂更多，让模型看到更少、更准。视频的详细度优先花在主体、事件、动作、变化和承接上。**
