# 提示词编译与一致性｜High-Signal Video Compiler

本文件负责把导演判断压成模型真正需要的执行语言。最终格式归 `output-contract-and-validation.md`；光影仅在当前任务需要时读取 `camera-light-quality-baseline.md`。

## 1. 核心原则

视频Prompt不是制作说明书，而是**时间中的可见事件**。

默认优先级：
`主体/产品 > 事件 > 动作/状态变化 > 可见完成态 > 空间连续 > 景别/机位/短运镜 > 必要声音/真实性 > 光影/成像 > 技术术语`

用户本轮若明确要求灯光、材质、摄影或画质返修，对应层级可以上调。

任何一句如果删掉后，主体、事件、动作、空间、镜头、材质、光色、时间、文字或声音都不变，就删除。

## 2. Global Once, Shot Specific

全局信息只定义一次：
- 片型/媒介/调性
- 人物、产品、空间真源
- 必要的主摄影质感
- 只有确实影响结果时才保留的主光/色彩基线
- 持续声音规则

分镜只写当前发生的变化。人物没有换衣、产品没有变、空间没有变化、主光没有变化时，不重复介绍。

同一事实禁止同时出现在开场、资产、光影、分镜多个位置。

## 3. 保留用户强表达，但抽象目标先转译

用户已经给出有效的事件、动作或镜头概念时，优先保留原意，不为了“专业”机械展开。

例如：
- `她看到价格后愣住，再看一眼。`
- `真实场景突然被产品接管。`
- `镜头后拉，发现刚才的真实场景其实是一张图片。`

这些本身已经是高信号。只有为了因果、连续性或高风险错误才补必要细节。

最终模型指令不能出现结果评价词，不只过滤某张禁词表。逐句判断：这句话描述能拍到/听到的内容，还是希望观众产生的效果？后者先转译再删除；标题、总控、声音同样适用。

| 后台目标（不下发） | 编译成具体设计 |
|---|---|
| 前3秒抓眼 | 从动作中进入：幼犬前爪刚搭上缸沿，画外手拿来浴巾，它立刻把爪子收回；用实际动作与反差开场 |
| 信息推进快 | 删除重复揉洗、重复反应，每镜引入取瓶、上洗液、起泡、冲净中的一个新变化 |
| 可爱、舒服 | 幼犬下巴压低、眼睛半闭，身体向按摩的手掌靠近 |
| 有感染力的推荐 | 短句连说，在关键词重读；画面同步给对应操作证据 |
| 音乐突出情绪 | 追躲时短促木琴与轻鼓点，停手时鼓点抽空，放松后拨弦进入 |

“泡沫被冲掉、湿毛贴服、杯底落桌”是可见物理完成态，必须保留。禁止的是传播效果、观众反应、审美评价和内部创作目的，不是动作的因果终点。固定对白或产品名原文不当作导演指令做关键词误删；事实是否获准另行核对。

## 4. Beat编译

关键Beat默认使用最短可读链：

`起始状态 → 触发 → 可见动作/变化 → 可见完成态 → 简短运镜`

不要求每次写满五项。简单镜头可压成一句。

示例：
`她看到价格后动作停住，低头重新核对，再抬头看朋友；镜头快速推近，在确认数字的一刻停住。`

复杂物理交互只保留必要因果：
`接近 → 接触 → 响应/变化 → 完成态`

只有穿戴、交接、液体、机械结构、连续变形等容易失败时，才补关键中间态。

## 5. 表演压缩

情绪优先转成短动作链，不默认展开面部肌肉清单：
- 震惊：`停住 → 核对 → 抬头`
- 怀疑：`盯住证据 → 迟疑 → 再确认`
- 紧张：`动作变小 → 呼吸收紧 → 视线快速确认出口`
- 松弛：`肩膀放下 → 呼吸变慢 → 轻笑`

只有面部特写、表演为主任务或用户要求FACS时，读取面部表情库展开。

## 6. 镜头与信息预算

每个明确镜头包含景别、观察方位与一条短运镜，快切子镜也不漏。直接写“侧面中景横跟，幼犬沿缸边挪步”，不先列全片摄影清单。剪辑约定归 `director-information-control.md`；叙事镜头常用极慢前推，不为形式差异强加大运镜。

篇幅先给人物/产品、事件、动作、空间接续。声音、光影、设备等修饰默认短于主体与动作叙述；不靠加长人物描写来配平。参考能锁定的身份不重写小传；音色每位一句，阶段语气并入对白。

按以下顺序压缩：删效果评价 → 删重复清单 → 删次要修饰 → 合并同义指令。不能删核心动作、接触因果、机位、声音身份和必要事实来凑字数。

## 7. 真实性补丁｜默认最多1条

完成主体、事件和镜头编译后，再判断：

`当前镜头最可能出现的一个AI错误是什么？`

只有答案明确，才加入一条最短的可见修正；没有明显风险就不加。

示例：
- 漂浮：`鞋底紧贴地面，保留轻微接触阴影。`
- 比例漂移：`产品尺寸和包装结构在推进中保持稳定。`
- 玻璃塑料感：`玻璃边缘保持透明折射，高光不过曝成死白。`
- 横移像贴图：`近景移动快于远景，形成自然空间视差。`
- 焦点混乱：`眼睛清晰，背景自然退焦。`
- 环境脱节：`火光只轻微影响人物朝向火源的一侧。`

不要把接触阴影、反弹光、高光滚降、景深、材质、空气透视、运动模糊全部列成固定套餐。

## 8. 光影与设备

光影是**可选控制层**，不是每条Prompt的固定主角。

只有它满足以下任一条件时才写：
- 直接影响主体是否读得清；
- 决定产品材质或卖点；
- 本身触发剧情或状态变化；
- 是当前成片的明确失败点；
- 用户明确要求摄影/灯光方案。

普通镜头通常不需要独立【光影】块。需要时，优先一条可见结果，而不是摄影术语列表。

设备名只在能带来明确可见结果时出现。不把 IMAX、ARRI、UE5、Octane、VFX、8K、HDR 叠成通用高级词包。

## 9. 复杂度决定长度

### 简单片段
单场景、单主体、一个主动作：一段或几句即可。

### 中等片段
多Beat、少量人物关系：总控 + 锁定 + 时间轴 + 必要声音/限制。

### 高控制片段
多人换位、复杂空间、产品连续、一镜到底、多场景光线切换、长片生产：才展开表演、空间、光影、声音等独立块。

**不是时长越长Prompt就必须越长；控制难度增加才增加文字。**

## 10. 最小状态账本

跨镜只继承真正会影响下一镜的变量：

`人物位置/朝向/认知｜手别与道具归属｜产品/环境状态｜相机/焦点｜必要主光｜声音｜完成态`

下一段从上一完成态继续。没有变化就不重复写。不可逆/阶段变化不能无因倒退：已湿→起泡→冲净→擦干不能重新回到首次打湿；冲净后不凭空再生泡沫；刚包浴巾不立即变全干蓬松。

用户给定首帧已处于中途，就从中途继续；若还需展示前序，明确设计回溯或先征得修改首帧的依据，不能静默重置。只有有意非线性叙事才标回溯，不用回溯为粗心错误补借口。

有对白时按 `voiceover-control.md` 逐时间窗核算；每镜可只有一个变化，介绍可覆盖多个镜头。先减重复信息和动作，再处理超时；不能让“镜头更密”变成“每镜塞更多动作”。

## 11. 冲突与污染检查

直接修正：
- 同时固定与环绕、同时前推与后拉等互斥镜头；
- 双手被占却执行第三个手部动作；
- 人物未到达却完成接触；
- 产品无因换款、换手、变大；
- 灯光无因随镜头换侧；
- 对结果提前反应；
- 精确对白重复出现；
- 同一个风格/质感词在多个分镜重复。

Prompt Pollution Audit：
1. 这句话是否直接影响视频结果？
2. 是否已在全局定义？
3. 是否只是解释一个模型已经懂的概念？
4. 是否只是为了显得专业？
5. 是否把可自由完成的实现锁得过细？
6. 光影/真实性描述是否开始比主体和事件更长？
7. 是否仍把抽象创意判断词直接丢给生成模型？

命中重复、解释性、低价值内容就删。

最终目标：**让Skill懂更多，让模型看到更少、更准。视频的详细度优先花在主体、事件、动作、变化和承接上。**
