# 30S NARRATIVE ENGINE｜30秒剧情带货主引擎

> 状态：`DEFAULT_ACTIVE｜BENCHMARK-DRIVEN`
>
> 目标：30秒默认不是“完整短剧”，也不是“15秒广告拉长”，而是用更强的剧情入口、情绪阶梯、Delay/Burst与Reaction赚取注意力，再让产品接管中后段，以Proof Ladder推动购买判断。
>
> 必须同时读取：`product-centered-narrative-gate.md`、`paid-social-rhythm-dna.md`、`performance-facs.md`、`scene-staging-compiler.md`、`prompt-attention-compiler.md`。

---

# 0. 默认时长策略

用户未指定时长时，剧情带货广告首推：`约30秒`。

15秒仍是正式合法短版：
- 只有一个强卖点/强Proof；
- Story Architecture天然在12–18秒完成；
- 继续拉长只会重复使用、重复Reaction或加入无关小戏；
- 用户/平台明确需要短版。

`DEFAULT = 30s`

但：

`30s ≠ 15s STORY + 15s FILLER`

如果没有足够高价值Beat，主动建议15秒。

---

# 1. 30秒的真正任务

15秒主要完成：
`购买问题 → 主要Proof → Decision / CTA`

30秒额外购买的是：
- 更强Hook；
- 更高情绪斜率；
- 持续冲突/任务压力；
- 精确短对白；
- Reaction切；
- Delay → Burst；
- Product Pivot；
- Product Takeover；
- Proof Ladder；
- Product Reframe / Decision Change。

不是购买：
- 人物背景；
- 完整人生小故事；
- 5秒继续走路；
- Reveal以后继续聊天。

核心：

`DRAMA EARNS ATTENTION`
→ `PRODUCT TAKES OVER`
→ `PROOF ESCALATES DESIRE`

---

# 2. 两种合法30秒路线

## ROUTE A｜DIRECT PRODUCT
产品或产品矛盾第一秒进入。

`PRODUCT HOOK`
→ `产品疑问/冲突`
→ `Detail / Evidence`
→ `Delay / Test`
→ `Reveal / Proof`
→ `Product Takeover`
→ `Decision`
→ `CTA`

## ROUTE B｜NEED-LED STORY
产品可延迟，但第一秒建立的必须是它能承接的商业需求。

`HIGH-EMOTION NEED HOOK`
→ `Need/Evidence升级`
→ `商业问题锁定`
→ `Product Pivot`
→ `Product Takeover`
→ `Proof Ladder`
→ `Decision`
→ `CTA`

禁止：
`完整小故事 → 突然插产品`。

---

# 3. 推荐节奏骨架｜功能优先，不机械卡秒

参考：

```text
0–3s   HIGH-EMOTION / HIGH-CURIOSITY HOOK
3–7s   NEW EVIDENCE / ESCALATION
7–10s  COMMERCIAL QUESTION LOCK
10–13s PRODUCT PIVOT / DELAY
13–18s PRODUCT REVEAL / FIRST PROOF
18–24s PRODUCT TAKEOVER + PROOF LADDER
24–27s PRODUCT REFRAME / DECISION
27–30s PRODUCT-DOMINANT CTA / HERO
```

如果产品第一秒出现，前10秒全部变成产品相关冲突/细节/购买问题升级。

重点不是每3秒一格，而是：
> **每1–3秒至少新增一个有价值的信息、状态、Reaction或Product Proof。**

---

# 4. Hook｜必须有情绪与视觉抓力

前1–3秒优先同时具备至少两个：
- 已经发生的事件；
- 强视觉异常/结果；
- 高情绪人物Reaction；
- 未完成问题；
- 新任务压力；
- 产品/商业需求矛盾。

不能只用台词说“现在很急”。

如果冲突是3–4/5：
- 人物动作更突然/迅速；
- 表情明确可读；
- 镜头允许轻手持、快速小推、短甩镜；
- BGM/SFX给Hook Hit。

`QUIET BRAND ≠ QUIET HOOK`

高端品牌可以克制美术，但Hook仍需要信息能量。

---

# 5. Escalation｜冲突必须新增事件，不重复说法

Hook之后每个高价值Beat至少新增一种：
- 新Evidence；
- 新Obstacle；
- 新Rule Pressure；
- 新Object State；
- 新Relationship Shift；
- 新Product Question。

禁止：
`没包？ → 你忘了 → 你什么都没有`

这只是同一事实换句话说。

正确：
`没包 → 周围确实没有包 → 衣服轮廓又看不到口袋 → Micro Anomaly`

冲突必须是“事情越来越具体”，不是“台词越来越多”。

---

# 6. Dialogue｜30秒不是多说话的许可证

对白服从 `prompt-attention-compiler.md`：

- 一个镜头一个明确Speaker；
- 2–4秒Beat最多1–2句核心短台词；
- 强Reaction / Product Action同Beat时优先只留1句；
- 精确台词用 `TIME｜SPEAKER｜EXACT LINE` 单独锁；
- Punchline/Decision句优先独占镜头。

对话必须完成：
- 商业问题；
- 冲突；
- 质疑；
- 验证；
- 事实；
- Decision Change之一。

不要为了“像短剧”让两个人不停聊天。

---

# 7. Emotion Ladder｜人物情绪必须有斜率

所有关键Beat读取 `performance-facs.md` 的1–5强度。

典型：

`冲突4 → 复核3 → Delay3 → Reveal Shock5 → Verify4 → Accept3/4`

关键Reveal不能只写“轻轻惊讶”。

强Reaction可短促达到5/5：
`眼神猛地锁住结果 → 双眉突然抬高 → 眼睛瞬间睁大 → 下颌松开/冻结0.4秒 → 快速复核 → 新判断`

核心：

`STRONG REACTION ≠ LONG REACTION`

Reaction通常0.3–1.0秒主要变化即可，随后立即进入Verify或新行动。

---

# 8. Camera × Emotion｜镜头与人物一起变化

### Conflict
`轻手持 + 快速小推 + 短促甩镜 + 景别收紧`

### Delay
`突然稳定 + Hold + 慢微推`

### Reveal
`硬切 / 局部突然打开到完整结果 / Full Result短停`

### Strong Reaction
`硬切近景/特写 + 很短微推`

### Product Takeover
`产品Detail / Use / Proof之间快速动作匹配硬切`

### Payoff / CTA
`镜头逐渐稳定、构图干净`

Camera仍服从Scene Staging、180°轴线和Actor Operability。

---

# 9. Delay → Burst｜必须是声画共同的反差

## Delay有效条件
- 观众知道答案快来了；
- 但关键结果暂时不可见；
- 人物视线已锁定；
- 镜头变稳；
- BGM压低/减少高频或短暂抽空。

无效Delay：
- 无意义慢动作；
- 简单动作拖3秒；
- 静止但没有期待。

## Burst
必须是具体事件：
- Product Reveal完整出现；
- Proof结果突然成立；
- 环境/规则突然变化；
- 关系/判断突然被改写。

Burst时：
- 结果先出现；
- 音乐Hit同步，不提前泄底；
- Reaction晚于可见Trigger。

---

# 10. Product Pivot / Takeover｜产品中后段必须接管

产品一旦成为答案：
- 减少人物闲聊；
- 镜头占比向Product Detail / Use / Proof倾斜；
- Reaction只作剪辑标点；
- 产品镜头越来越具体。

30秒常见：
- 约8–14秒Product Pivot；
- 约15秒以后多数高价值镜头属于产品；
- 27–30秒不是第一次真正展示产品。

`PRODUCT TAKEOVER > POST-REVEAL DRAMA`

---

# 11. Proof Ladder｜后半不是重复展示

Product Takeover后至少2级不同证据。

示例服装：
`完整上身`
→ `材质/结构近景`
→ `侧面比例`
→ `动态/坐下/生活状态`
→ `Hero`

示例便利店：
`品牌地点成立`
→ `冷饮/零食/热食等选择`
→ `购物完成状态`
→ `真实生活结果`
→ `品牌Hero`

每一级增加新信息。

若第三个复杂实体交互会超过生成负载，优先用视觉结果/Reaction/Decision替代。

---

# 12. Scene Staging｜元素多时先安排关系

30秒广告切场景多，更容易出现“元素都对，但事件方向错”。

涉及：
- 进/出门；
- 上/下车；
- 商店/餐厅/品牌地点；
- 人物 + 道具 + 品牌3个以上元素；

先执行：

`EVENT MEANING → START → END → FROM/THROUGH/TO → ACTOR FACING → DEPTH LAYERS → CAMERA → BRAND`

例如离店：
`店内 → 门 → 店外 → 远离店门`。

不是写一句“人物离开，背景看到品牌”让模型自己猜。

---

# 13. Audio / BGM｜必须有事件地图

内部建立：

```text
HOOK AUDIO CUE:
DIALOGUE BED:
ESCALATION SFX:
DELAY DROP:
PRODUCT PIVOT HIT:
PROOF MONTAGE RHYTHM:
PAYOFF RELEASE:
CTA END HIT:
```

默认：
- Hook Hit；
- 对白BGM让位；
- 新事件SFX标点；
- Delay压低/抽空；
- Reveal/Pivot结果出现同时Hit；
- Proof Montage节拍更密；
- Payoff放松；
- CTA干净End Hit。

禁止只写“高级BGM，高潮加强”。

---

# 14. 生成复杂度｜30秒信息更多，单镜任务更少

仍然：
- 一镜一项高风险精细接触；
- 一个Beat一个Primary Event；
- 精确对白、强Reaction、复杂产品操作不要同时抢同一秒；
- 复杂位移先Scene Staging；
- 产品/道具状态先Physical Logic；
- 穿戴状态替换明确结束旧State；
- Prompt最终执行 `prompt-attention-compiler.md` 压缩。

如果一个Beat需要靠大量规则解释才成立：
> 拆Beat或简化故事，不继续加提示词。

---

# 15. 30秒Silent QA

- [ ] 默认30秒有足够高价值Beat；若无，已建议15秒
- [ ] 首3秒事件/视觉/Reaction足够抓人，不靠纯解释台词
- [ ] 前10秒每1–3秒有新信息/状态/Reaction
- [ ] 冲突Evidence真正新增信息，不重复同一事实
- [ ] 对白没有过载，一镜一个Speaker
- [ ] 情绪强度有阶梯，关键Reveal Reaction没有被压平
- [ ] 运镜随情绪变化：Conflict紧、Delay稳、Reveal Hit、Payoff稳
- [ ] 至少一次有效Delay → Burst
- [ ] 产品在中后段真实接管，不是最后才出现
- [ ] 后半至少2级不同Proof
- [ ] Product Pivot后没有继续长人物支线
- [ ] 复杂场面已通过Scene Staging，不存在方向语义反转
- [ ] BGM/SFX有Hook、让位、Drop、Hit、Montage、CTA节点
- [ ] 每个Beat只有一个Primary Event
- [ ] Prompt已压缩，未用几十条负面词补丁
- [ ] 27–30秒CTA默认高清Product Hero，无生成文字（除非用户明确要求）

最终：

`30S IS A PRODUCT-CONVERSION ARC, NOT A MINI TV EPISODE.`

`STORY HOOKS → PRODUCT TAKES OVER → PROOF SELLS.`
