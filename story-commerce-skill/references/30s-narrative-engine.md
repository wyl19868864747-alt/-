# 30S NARRATIVE ENGINE｜30秒剧情广告叙事与表演引擎

> 状态：`PRELAUNCH_CANDIDATE`
>
> 目标：把30秒剧情广告从“15秒广告拉长”升级成真正有Hook、持续冲突、对白、Reaction、延迟、爆发、产品介入、质疑、Proof、信息变化/反转、信服与商业收尾的完整短剧情。
>
> 本模块必须服从：`PRODUCT TRUTH > STORY TRICK`、`PROOF > REVERSAL`、`PRIMARY ARCHITECTURE > OPTIONAL MODULES`。

---

# 0. 默认时长策略

用户未指定时长时，剧情带货广告首推：`约30秒`。

15秒仍是合法且重要的短版：
- 当卖点只有一个强Proof；
- Story Architecture天然在12–18秒内完成；
- 继续拉长只能增加重复使用、无意义背景事件或TV Drama Drift；
- 或平台/用户明确需要短版时。

因此：

`DEFAULT RECOMMENDATION = 30s`

但必须同时遵守：

`30s ≠ 15s STORY + 15s FILLER`

如果故事没有足够的高价值Beat支撑30秒，必须明确建议15秒，而不是填时长。

---

# 1. 30秒与15秒的本质区别

15秒主要解决：
- 一个商业问题；
- 一个主要Proof；
- 一个清楚的状态变化；
- 一个简洁Decision / Payoff。

30秒必须额外提供：
- 更强的开场事件；
- 持续推进的冲突发动机；
- 人物关系或任务压力；
- 至少一次有效对白交锋；
- 至少一次独立Reaction镜头或Reaction Beat；
- 一次延迟/等待/蓄力；
- 一次爆发/结果释放；
- 对产品或解决方案的质疑/验证；
- 更完整的信息变化、信服或Decision Shift；
- 结尾干净商业Hero。

30秒的价值不是“讲更多产品参数”，而是：

> **让观众先卷入事件，再让产品成为改变事件走向的关键因果。**

---

# 2. 30秒剧情功能链｜不是死时间表

30秒默认至少完成以下功能中的大多数：

`强Hook`
→ `持续冲突 / 任务压力`
→ `对白交锋`
→ `Reaction`
→ `延迟 / 蓄力 / 未完成事件`
→ `爆发 / 新结果`
→ `产品介入或产品意义升级`
→ `质疑 / 不信 / 验证要求`
→ `Proof`
→ `信息变化 / Reveal / Surprise / True Reversal（若通过R2 Gate）`
→ `打破旧判断 / 旧规则`
→ `信服 / Decision Change`
→ `高清产品Hero CTA`

注意：
- 这是一组剧情功能，不要求每条机械使用完全相同顺序；
- 产品可以早出现，但真正的商业答案/Proof可以延迟；
- 不为了“悬念”把产品藏到最后几秒；
- 强反转只有在R2 Gate通过时使用，不能因为是30秒就伪造Wrong Answer；
- 如果R2不成立，用强Escalation + R1 Reveal/Surprise + Proof Payoff代替。

---

# 3. 推荐30秒节奏骨架

这是默认参考，不是固定模板：

## 0–3s｜强Hook
必须已经在事件中。

优先：
- 冲突正在发生；
- 异常结果已经出现；
- 人物正在阻止/追赶/验证某件事；
- 一个未完成事件明显需要答案；
- 强视觉变化或行为异常。

不能只靠一句台词说“出事了”。

## 3–8s｜冲突继续，不立刻解决
Hook之后必须继续产生阻力。

至少发生一个：
- 新证据；
- 新障碍；
- 第二人物介入；
- 任务失败一次；
- 旧判断被进一步强化；
- 环境/规则施加压力。

## 8–12s｜对白 + Reaction
至少一次真正的剧情对白交换。

对白不能只是念卖点。

推荐：
`A提出问题/判断 → B回应/反驳/确认 → Reaction → 新行动`

Reaction独立可读，不要边说长句边同时完成复杂动作。

## 12–16s｜延迟 / 蓄力 / Hold
让观众短暂等待答案。

可用：
- 人物停半拍再验证；
- 产品接近但结果暂时不揭晓；
- 镜头停在关键动作前；
- 环境继续施压；
- 小异常出现；
- 角色产生“真的？”的短暂停顿。

延迟必须制造期待，不是拖慢。

## 16–20s｜爆发 / 产品因果转折
这里通常发生一项高价值变化：
- 产品真正介入；
- Proof开始；
- 事件突然升级；
- 强视觉结果出现；
- 旧规则被打破。

爆发必须是具体动作/结果，不写“此处爆发”。

## 20–24s｜质疑 / 二次验证
30秒最容易比15秒多出来的高价值区域。

角色不能第一次看到产品就立刻无条件信服。

可出现：
- “Wait, really?”
- 再看一次结果；
- 对照验证；
- 第二人物挑战；
- 再做一次短Proof；
- 验证有没有隐藏条件。

但不能为了质疑而编造商品不存在的问题。

## 24–27s｜信息变化 / 反转 / 规则改写
优先级：
1. 若R2 Gate通过：True Reversal；
2. 若不通过：R1 Reveal / Surprise / Clarification；
3. 若R0最合适：用Proof Payoff / Social Position Shift / Goal Success形成高潮。

30秒允许强反转，但不强制假反转。

真正有效的“打破规则”必须改变：
- 人物原判断；
- 关系优势；
- 任务结果；
- 产品意义；
- 观众对前文的理解。

## 27–28.5s｜信服 / Decision Change
必须落到动作：
- 买；
- 选；
- 开始使用；
- 放弃旧方案；
- 把产品交给/推荐给另一人；
- 进入下一行动。

不只写“她信服了”。

## 28.5–30s｜CTA / Product Hero
默认：
- 放大的高清产品；
- 干净背景或浅景深；
- 极轻推近或稳定定格；
- 不默认生成CTA文字。

除非用户明确要求，不生成`Learn More`、按钮、复杂价格卡或长文案。

---

# 4. 30秒持续冲突原则

Hook不能完成自己的使命后就消失。

必须形成：

`HOOK EVENT`
→ `CONSEQUENCE`
→ `NEW OBSTACLE / NEW EVIDENCE`
→ `CHARACTER RESPONSE`
→ `PRODUCT-RELATED TURN`

每约2–4秒应有至少一个新的高价值Beat：
- 新信息；
- 新动作；
- 新Reaction；
- 新Proof；
- 新阻力；
- 新关系变化；
- 新状态变化。

禁止：
- 连续5–10秒人物只是继续工作/继续走路/继续使用；
- 背景事件很热闹，但不改变人物/产品/观众理解；
- 为了时长加入与商业因果无关的小剧情。

---

# 5. 对白镜头与Reaction镜头

30秒默认允许人物“演”，但表演必须推动故事。

## 对白镜头
每句台词至少完成一项：
- 提出问题；
- 建立错误判断；
- 质疑；
- 推动验证；
- 暴露Top Hesitation；
- Punchline；
- Decision Change。

## Reaction镜头
Reaction要晚于Trigger：

`事件/Proof`
→ `视线锁定`
→ `短促面部变化`
→ `Micro Pause`
→ `新动作/短句`

30秒可以给Reaction更多时间，但不是持续瞪眼。

推荐在关键节点独立给0.5–1.5秒Reaction Beat：
- Hook后；
- Delay后；
- Proof后；
- Reversal后。

---

# 6. 延迟画面与爆发画面

## DELAY SHOT｜延迟
目的：让观众预判即将发生什么，但暂时不给答案。

有效Delay：
- 手停在按钮/产品前；
- 人物盯住结果半秒；
- 关键门/盒盖/屏幕即将打开；
- 第二人物等答案；
- 声音先停/退，再给结果。

无效Delay：
- 无意义慢动作；
- 简单动作硬拖3秒；
- 静止镜头没有新的期待。

## BURST SHOT｜爆发
必须明确写发生什么：
- 环境突然响起/打开/涌入；
- 人物快速动作；
- 产品Proof瞬间成立；
- 视觉状态突然变化；
- 关系地位突然翻转。

`DELAY → BURST`优先成对使用，制造节拍反差。

---

# 7. 质疑与信服链

30秒默认比15秒更适合加入Top Hesitation。

推荐：

`产品出现`
→ `角色不立即全信`
→ `一句真实质疑`
→ `验证动作`
→ `Proof`
→ `Reaction`
→ `Decision Change`

质疑必须来自真实消费者问题，不能为了戏剧性造假。

例如：
- “Does it actually fit all that?”
- “That’s really included?”
- “And it still closes?”

禁止伪造认证、医学效果、精确性能或不存在的隐藏条件。

---

# 8. 30秒反转策略

30秒提供了更足够的R2预算，但仍从R0开始路由。

## R2适用时
可以形成：

`Wrong Answer`
→ `Evidence 1`
→ `Evidence 2`
→ `Delay / Micro Anomaly`
→ `Reveal`
→ `前文重解释`
→ `Proof`
→ `Decision Change`

## R2不适用时
禁止为了满足“30秒一定强反转”伪造逻辑。

改用：
- R1 Surprise；
- R1 Reveal；
- Clarification；
- Social Position Shift；
- Goal Success；
- Proof Burst。

原则：

`STRONG PAYOFF > FAKE REVERSAL`

---

# 9. 30秒产品出现策略

产品不一定等到15秒才第一次出现。

可以：
- 早期作为争议对象出现；
- 早期作为未解释道具出现；
- 早期露出但延迟Proof；
- 中段成为解决事件的关键工具。

但必须避免：
- 前20秒完全看不到产品，只在结尾突然塞入；
- 一开始就完整解释所有卖点，导致后20秒无事可讲。

最佳状态：

> **产品早有存在感，真正的意义/Proof在中后段逐步释放。**

---

# 10. 30秒生成复杂度控制

30秒允许更多剧情，不代表一个镜头承担更多物理动作。

仍然遵守：
- 一镜一项高风险精细接触；
- 复杂产品操作主动切镜；
- 对白、Reaction、产品Proof尽量不要在同一秒内互相抢任务；
- 多人物时优先减少递物、交叉手部与同步动作；
- Physical Logic DNA、Camera×Action、Product Lock继续生效。

如果30秒需要靠增加高风险动作才能填满：
> 缩剧情复杂度，不增加物理复杂度。

---

# 11. 30秒Silent QA

- [ ] 首3秒已经发生事件，不是台词说明事件。
- [ ] Hook在后续继续产生后果，而不是3秒后消失。
- [ ] 3–27秒至少每2–4秒出现一个高价值新Beat。
- [ ] 至少一次有效对白交换。
- [ ] 至少一次独立可读Reaction Beat。
- [ ] 至少一次Delay / Hold。
- [ ] 至少一次Burst / Payoff。
- [ ] 产品不是结尾才突然出现。
- [ ] 产品真正改变剧情走向，而不是中插广告。
- [ ] 至少一个Top Hesitation被剧情化验证，若商品不需要则明确跳过。
- [ ] R-level仍由Reversal Router决定，没有因为30秒强行伪造R2。
- [ ] 若R2成立，前文Evidence、Micro Anomaly、Reveal、Aftermath完整。
- [ ] 若R2不成立，仍有足够强的Proof Payoff / R1 / Goal Success。
- [ ] 对白、Reaction、Proof、物理动作没有挤在同一时间段过载。
- [ ] 没有5秒以上“继续使用/继续工作/继续走路”的平台期。
- [ ] 27秒前已经完成商业信服/Decision Change。
- [ ] 最后约1.5–2秒为干净高清产品Hero，默认无生成文字。

---

# 12. 当前上架前验证重点

本模块暂不直接替代主Skill默认时长规则，先通过真实Seedance 30秒压力测试验证。

优先验证：
1. 双人对白 + 持续冲突 + Reaction；
2. Delay → Burst节拍是否可执行；
3. 产品中段介入是否自然；
4. 质疑 → Proof → 信服是否商业清楚；
5. R1/R2是否能在30秒内完整而不电视剧化；
6. 30秒是否保持Commercial Beat Density；
7. Physical Logic / Product Lock是否在更长时长中仍稳定。

通过真实测试后，再升级为主Skill默认30秒策略。
