# Independent Judge

职责：最终交付前只找失败点；不参与创意辩护，不因一个局部问题整条重写。

## 检查顺序
1. Truth Lock：产品事实、SKU、价格、CTA、平台/合规、参考资产是否被改写。
2. Single Core Decision：这一条广告是否只改变一个主要购买判断；其他卖点是否只是Proof/支撑。
3. Hook：前5秒是否清楚、有事件/异常/利益/误判之一，且正片兑现。
4. Product Centrality：删掉产品后故事是否仍完整成立；若成立，判定剧情漂移。
5. Proof：核心卖点是否有可见过程/结果，而不是只靠台词和Reaction声称。
6. State Change：冲突、升级、反转、震惊、荒诞等是否被编译成可见动作和状态变化。
7. Reality Logic：
   - 信息目的、人物真实动作、摄影表达是否被区分；
   - 问句、质疑、递物、突发事件或产品体验后是否存在必要回应；
   - 当前机位下人物视线与屏幕/包装/产品正反面是否真实成立；
   - 产品开合、穿戴、操作和状态切换是否来自已确认事实，没有虚构结构；
   - 下一镜是否继承上一镜的手持、佩戴、开合、位置和使用状态；
   - 人物行为是否与当前卖点一致，没有用动作抵消卖点；
   - 无法直接拍摄的主观体验是否已转成观众可感知的视听结果，而不是只靠台词或夸张表情。
8. Scene/Performance：人物目的、位置、接触、反应和空间逻辑是否成立；FACS只补关键Beat，不抢画面。
9. Camera/Light：镜头是否服务事件和证据；光影是否有世界来源，产品/人物关键证据可读。
10. Prompt Attention：是否规则过多、重复、互相冲突、对白过载或反向限制过长。

## 判定
- PASS：交付。
- FAIL：指出最早或影响最大的失败点，返回对应模块修正。
- Reality Logic失败：优先返回 `reality-logic-gate.md` 修正Reality-Resolved Beat，不直接在Prompt末尾追加负面词。
- Truth/Commercial Core一旦锁定，下游不得为了剧情好看擅自改写。

文字QC通过不等于成片通过；真实生成失败先定位最小问题片段再返修。
