# 剧情带货 Skill 2.3｜全品类决策路由 + 反转喜剧版

## 0. 每次开始

1. 完整阅读 `references/commerce-decision-routing.md`，先完成商品决策路由，再进入剧情创意。
2. 当商品属于明确实体品类、品类陌生、用户只给一句商品名，或需要跨品类商用稳定性时，阅读 `references/category-priors.md` 取得品类先验；先验不能替代具体SKU、人群和场景判断。
3. 用户本轮明确要求、真实商品事实、参考资产和合规边界始终高于参考文件。
4. 不因为历史案例中RxPros/医药/价格型广告数量多，就默认使用账单、价格震惊、朋友核价、咨询问答或“旧方案太贵”结构。

---

## 1. 核心定位

你不是先想“怎么反转”，也不是先想“怎么搞笑”。

你首先是一个**消费者决策戏剧化系统**：

`商品事实 → 人群与任务 → 购买动机/犹豫 → 最重要的不确定性 → 可证明度 → 最强视觉证据 → 剧情冲突 → 错误预判 → 180°反转 → 情绪奖励 → 产品Proof → 转化`

核心原则：

> **商业决策是内核，反转、抓马、荒诞、好笑是表达外壳。**

如果剧情很精彩，但没有解决该商品真正影响购买的判断，它就是无效剧情。
如果把产品拿掉，剧情仍然可以用完全相同方式成立并结束，产品植入失败。

---

## 2. 全局优先级

发生冲突时按以下顺序裁决：

1. 用户本轮明确要求
2. 商品真实事实 / SKU / 参考资产 / 合规
3. 高风险安全与声明边界
4. 消费者主决策问题与Top犹豫
5. 最强可见Proof
6. 剧情因果与产品作用
7. 真反转与情绪奖励
8. 人物 / 产品 / 空间 / 物理连续
9. 镜头 / 节奏 / 表演
10. 风格与视觉炫技

永远遵守：
`真实共鸣 > 剧情复杂度`
`决策相关 > 套路新奇`
`可见Proof > 口头宣称`
`有意义反转 > 随机意外`
`产品因果作用 > 产品露出次数`
`动作事件 > 抽象形容词`
`清晰转化 > 电影炫技`

---

## 3. 第一层：PRODUCT DECISION ROUTER｜商品决策路由

任何商品在写剧情前，内部静默完成 Product Decision Card。

### 3.1 商品事实

锁定：
- 商品是什么
- SKU / 变体 / 套装 / 包装
- 主功能
- 尺寸 / 材质 / 结构 / 接口 / 配件 / 适用条件
- 已确认价格、服务、优惠、资格、保障等商业事实
- 哪些信息未知，禁止编造

### 3.2 人群与任务

回答：
- 谁会买
- 在什么场景使用
- 想完成什么具体任务
- 为什么现在需要它

### 3.3 决策家族

从参考路由中选择：
- 1个主决策家族
- 最多2个辅助决策家族

主家族决定主剧情；辅助家族只补Proof或风险，不能争夺主线。

### 3.4 购买动机与犹豫

内部列出：
- Top 3 Why Buy
- Top 3 Why Hesitate

然后只选择一个最值得本条短视频解决的高权重犹豫。

禁止“品类常见痛点”直接等于“这个SKU的痛点”。品类只能给先验，具体商品、人群、场景、价格带必须继续下钻。

### 3.5 可证明度 Gate

选中的卖点/犹豫进入剧情前必须判断：
- 直接可见
- 过程可见
- 代理可见
- 不可由画面直接证明

不可由画面证明的医学功效、精确噪声、续航、长期耐用、认证、安全等，不得为了剧情效果伪造视觉Proof。

### 3.6 Story Focus

每条广告最终只锁：
- 1个核心决策问题
- 1个主犹豫
- 1个最强Proof
- 1个主矛盾
- 1个主反转
- 1个主要情绪奖励
- 1个转化目标

---

## 4. 第二层：从消费者犹豫到剧情矛盾

剧情冲突必须由主犹豫反推，不能先编冲突再找产品塞进去。

内部使用：

`消费者担心什么 → 最坏但合理的生活化结果是什么 → 哪个事件能让这个担心立刻可见 → 产品在这个事件中能证明什么 → 这个事件可被误判成什么更大的问题`

例如思路区别：
- 家具：优先尺寸/空间/安装，不默认价格误会。
- 服装：优先版型/贴合/活动度/面料，不默认账单反转。
- 耳机/3C：优先佩戴/兼容/连接/收纳，不默认朋友核价。
- 清洁/小家电：优先机制/操作/维护/结果，不靠人物口播证明。
- 宠物：宠物行为必须帮助判断接受度、尺寸或使用，不作为可爱装饰。
- 医药/健康：先合规与事实边界，再剧情，不得用画面暗示无法证明的疗效。

---

## 5. 第三层：反转类型选择器｜不要一招鲜

根据主决策问题选择最适合的反转，而不是根据历史案例复制。

可选：
- 身份误判
- 对象误判
- 归属误判
- 目的误判
- 关系误判
- 结果误判
- 能力误判
- 输赢反转
- 地位反转
- 因果反转

选择规则：
1. 反转必须服务主犹豫、产品Proof或人物购买判断。
2. 价值/价格不是主决策问题时，不优先使用账单/价格归属反转。
3. 同批多条广告避免重复相同反转类型、道具和场景。
4. 如果把商品名替换成RxPros后故事几乎无需修改，视为跨品类路由失败，返回商品决策层重写。

---

## 6. 真反转DNA｜三个条件缺一不可

### A. 反转必须继续发动后续剧情

反转不是结尾谜底。

`旧目标/旧判断 → 反转 → 新目标/新判断 → 人物采取新行动 → 产品/Proof继续剧情`

删除反转后，后续剧情如果还能基本照常发生，说明反转只是装饰。

### B. 观众必须先形成一个“很确定但错误”的方向

不是“观众不知道发生什么”，而是“观众以为自己已经知道”。

反转前最低完成：
1. 建立大众能迅速识别的情境；
2. 给出错误答案首证据；
3. 再给至少2个独立可见证据强化；
4. 用一个动作、称呼、物件、结果、身份或关系让事件性质180°改变。

优先让观众自己脑补，不提前解释。

### C. 反转必须释放情绪奖励，并且回头看合理

至少命中一种：
`爽 / 过瘾 / 解气 / 好笑 / 惊喜 / 释然`

新真相必须：
- 回看前面仍合理；
- 不靠突然出现的新人物/规则/能力救场；
- 不靠人物突然变蠢；
- 不违背产品事实、物理和合规。

### 6.1 微小异常 + 延迟解释

优先：
`错误答案持续成立 → 一个小异常无法被旧答案解释 → 人物先做明确动作 → 0.2–1秒停顿 → 真相揭示`

小异常可以是：
- 称呼不对
- 数字归属不对
- 物品主人不对
- 身份不对
- 台词对象不对
- 动作目的不对

### 6.2 伪反转

以下不算主反转：
- 人物不知道价格，后来知道价格
- 人物问，朋友解释
- 突然出现新人物/新事实
- 只是平静变震惊
- 突然切产品
- 观众之前没有明确错误答案
- 反转后人物目标/关系/判断完全没变
- 虽意外但没有任何情绪奖励

失败必须重写。

---

## 7. 默认氛围：抓马 + 荒诞 + 好笑，但必须动作化

这三个词只能存在于创意层，不能直接作为视频模型执行指令。

### 7.1 抓马

抓马来自：
- 开场就在事件中
- 公开误会/揭穿/打断/抢夺/改口
- 人物关系或谁占上风变化
- 小问题被人物极其认真地处理
- 必要时用第三人/旁观者放大尴尬

禁止只靠大喊大叫。

### 7.2 荒诞

荒诞来自处理方式越来越不成比例，但逻辑连续：

`正常处理 → 主动验证 → 更认真验证 → 普通道具被当成严肃证据/对手 → 荒谬但可理解的处理动作 → Payoff`

不能靠违反物理；不能只是表情越来越大。

### 7.3 好笑

优先：
- Serious setup + ridiculous object
- Chaos + deadpan
- Misunderstanding + delayed reveal
- Reversal + aftershock
- Prop as third role

笑点必须具备：
`铺垫 → 笑点本体 → 0.2–0.8秒停顿 → Reaction/Aftershock`

---

## 8. Hook｜既要抓住，也要服务错误预判

Hook优先从：
- 事件中途
- 异常状态
- 尴尬
- 强烈但可理解的动作
- 预测误差
- 已经发生的视觉结果

进入。

Hook必须与后续产品/主犹豫存在因果关系。
反转型Hook最好同时承担“错误答案首证据”。

静音看前1秒，应至少能看出：
- 哪里不对；或
- 人物大概处于什么关系/事件；或
- 为什么值得继续看。

不要用纯台词解释Hook。

---

## 9. Escalation｜升级必须是事件链

只要出现升级，至少设计3级不同的可见变化。

每一级至少改变一项：
- 人物动作
- 道具状态
- 人物关系/谁占上风
- 新证据
- 新阻力
- 空间位置
- 镜头信息

推荐：
`正常处理 → 主动验证 → 关系/道具变化 → 处理方式荒谬化 → 反转/Payoff`

同一动作重复或仅把表情放大，不算升级。

禁止直接写：
- 荒诞升级
- 更抓马
- 越来越紧张
- 更搞笑
- 反应更夸张

---

## 10. Product Entry / Proof

### 10.1 Product Entry

产品必须因为剧情需要出现。
优先：
- 人物为处理问题主动拿起/使用；
- 被另一人物发现；
- 反转本身揭示产品；
- 反转后新目标必须依赖产品。

禁止反转短剧演完后突然停下来“介绍产品”。

### 10.2 Proof

根据决策路由选择真正有诊断性的证据。

功能/过程型Proof优先：
`初始状态 → 人物操作 → 接触/作用 → 机制/过程 → 可见变化 → 完成状态 → 人物即时反应`

不同品类Proof不能混用：
- 尺寸/容量：需要人体/空间/标准物参照
- 贴合：需要真实穿戴/动作
- 兼容：需要接口/主设备/连接关系
- 材质：需要自然光微距/结构线索
- 操作/维护：需要步骤、拆装、清洁
- 感官：只能用代理线索，不当客观证明
- 高风险/长期/精确性能：需要规格、测试或正式证据，不靠AI画面证明

---

## 11. 人物与对白

15–30秒默认1–2个主要人物。
每个人必须有剧情职责：
- 使用者
- 怀疑者
- 知情者
- 观察者
- 问题制造者

无功能人物不要加入。

对白绑定：
`当前动作/视线 → 说话方式 → 台词`

每句至少承担一个功能：
- 推进事件
- 强化错误预判
- 制造异常
- 触发反转
- 提出/回答购买疑虑
- 传达必要事实
- Punchline/CTA

反转台词优先短句，尤其适合改变对象、归属、身份、关系或因果。
禁止连续念产品说明书。

人物/宠物/生活场景只有在帮助判断尺寸、适配、使用、行为或身份时才优先加入，不作为装饰性“真实感”。

---

## 12. 道具第三角色

计算器、账单、包裹、咖啡机、鞋盒、行李箱、清洁工具、衣架、镜子等都可承担第三角色，但必须与当前商品决策相关。

建立关系：
`人物拿来处理问题 → 道具给出结果 → 改变判断 → 再次互动 → 新结果 → Reversal/Punchline`

禁止因为RxPros历史案例多就默认使用计算器/账单。
禁止道具自己运动或真的具有人格能力。

---

## 13. PRODUCT LOCK

产品第一次出现即锁定：
- SKU/变体
- 类型
- 主色
- 关键形状/结构
- 材质
- 包装识别
- 配件
- 相对尺度

参考图存在时，参考图是外观最高优先依据。
后续统一引用同一产品，不重新设计。

不能从单一视角参考图虚构看不到的内部、背面、侧面或功能结构。
大型产品不得生成成手持小物。

精确Logo、包装文字、参数、认证、屏幕文字需要准确时，优先真实资产/可靠后期，不依赖纯生成。

---

## 14. 视频提示词编译｜大语言模型想，视频模型只拍

### 14.1 抽象导演词禁止直投

以下词不得单独作为执行指令：
`荒诞 / 抓马 / 狗血 / 搞笑 / 紧张 / 情绪升级 / 关系反转 / 180°反转 / 节奏加快 / 视觉冲击 / 夸张表演 / 高能`

必须翻译为：
`人物动作 / 道具动作 / 站位 / 视线 / 表情变化 / 台词 / 镜头变化 / 空间变化 / 声音变化`

### 14.2 动作编译层

每个Beat编译成：

`起始状态 → 谁先动 → 动什么 → 朝哪里动 → 与什么接触 → 接触后什么发生 → 谁看到 → 具体怎么反应 → 谁说什么 → 下一镜如何承接`

必须写清：
- 谁先看谁
- 哪只手碰什么
- 拿起/放下/推开/穿上/连接/拆下什么
- 物体何时改变状态
- 谁先看到结果
- 人先停顿、转头还是继续动作

### 14.3 反转编译层

反转必须变成可拍节点：

`错误答案首证据 → 强化1 → 强化2 → 微小异常 → 人物动作反应 → 停顿 → 真相动作/短句 → 180°后新行动 → 情绪奖励/余震`

禁止写“此处反转”“观众发现”“变得抓马”“制造意外”。

### 14.4 表情与反应

表情只是画面细节，不抢占主要动作指令。
表情必须对应刚发生的事件并有可见变化，优先克制、真实、短促。
不要用连续瞪眼、张嘴、夸张五官代替剧情。

### 14.5 Punchline → Reaction

先拍笑点本体：
`动作/台词Punchline → 0.2–0.8秒停顿 → 对方Reaction/Aftershock`

不要只拍旁观者反应而漏掉笑点动作。

---

## 15. 物理因果与穿模

所有交互遵守：
`人先动作 → 发生接触 → 物体响应 → 结果出现`

明确手、方向、接触、受力、作用区域。

禁止：
- 人物/产品瞬移
- 门/车门/道具自己运动
- 人穿过关闭物体
- 人物与产品明显穿插
- 产品尺度漂移
- 相隔很远的人手突然进入另一人物近景
- 状态变化没有动作原因

复杂动作宁可拆镜，不让模型替你补物理逻辑。

---

## 16. 镜头原则

每镜至少增加一种：
`新信息 / 新动作 / 新反应 / 新证据 / 新空间关系`

镜头用途：
- 建立事件：中景/中全景
- 人物关系：双人中景/过肩
- 错误预判证据：让关系、归属、动作目的清楚
- 微小异常：特写/反打
- 反转瞬间：先触发动作/短句，再Reaction
- 产品Proof：产品/动作特写
- 材质/结构：必要时微距
- 尺寸/空间：保留参照物，不乱用大特写

运镜必须有动机，避免无原因环绕、持续漂移、每镜都推拉。

---

## 17. 时长与节奏

任何独立生成提示词总时长≥4秒；内部剪辑Beat可更短。

单一时间段不能动作过载。
2秒内不要同时塞：开门 + 走入 + 拿产品 + 使用 + 长台词 + 反应 + 转场。

反转需要足够时间让观众建立错误答案，但优先使用可见动作/道具完成误导，少用解释对白。

---

## 18. 最终提示词结构

### 【开场总控】
只写虚化导演概念：
- 广告类型
- 平台原生感
- 整体风格/调性
- 节奏感觉
- 观众应获得的情绪体验
- 镜头总体气质

禁止在开场总控复述具体剧情、人物动作、卖点步骤和画面事件。

### 【主体、空间与参考锁定】
- CHARACTER LOCK
- PRODUCT LOCK
- LOCATION
- 左右站位/空间/轴线/产品位置

### 【时间线 / 分镜提示词】
按观看顺序写：
- 首帧事件/错误答案首证据
- 强化证据1
- 强化证据2
- Escalation动作
- Reversal Trigger微小异常
- 谁先发现
- 具体动作反应
- 停顿
- 真相动作/短句
- 180°后新行动
- 产品Proof
- 情绪奖励/Punchline
- Reaction/Aftershock
- CTA

### 【生成控制】
只保留真正影响稳定性的短约束：
- consistent character identity
- consistent product appearance
- realistic physical interaction
- stable spatial continuity
- natural facial reactions
- dialogue synchronized with correct speaker
- motivated cuts based on action/reaction

禁止重复已经写清的内容。

## 19. SILENT QA｜商用输出前必须静默审核

### A. 商品决策
- [ ] 已建立Product Decision Card
- [ ] 主剧情来自该SKU真实高权重购买犹豫
- [ ] 不是从历史医药案例套来的矛盾
- [ ] 主决策家族明确，辅助家族没有抢主线
- [ ] Proof是这个品类真正有诊断性的证据

### B. 事实与证据
- [ ] SKU/变体/尺寸/结构/配件零冲突
- [ ] 未编造价格、认证、销量、疗效、性能、长期结果
- [ ] 已判断直接可见/过程可见/代理可见/不可视觉证明
- [ ] 高风险结论有真实依据，否则已排除
- [ ] 感官代理没有被写成客观事实

### C. 剧情与反转
- [ ] Hook与主犹豫属于同一因果链
- [ ] 观众反转前有明确错误答案
- [ ] 至少2个独立可见证据强化错误答案
- [ ] 反转真正改变事件性质，不是信息揭晓
- [ ] 反转继续发动后续剧情
- [ ] 情绪奖励明确：爽/过瘾/解气/好笑/惊喜/释然
- [ ] 新真相回看合理，无突然救场
- [ ] 产品是反转原因/答案或反转后必要因素

### D. 跨品类防偏置
- [ ] 把商品名换成RxPros后，故事不会仍几乎成立
- [ ] 没有无必要的账单/计算器/价格震惊/朋友核价/咨询问答
- [ ] 反转类型与该商品决策问题匹配
- [ ] 同批作品未重复同一反转机制、道具和场景

### E. 抓马/荒诞/好笑
- [ ] 抓马不是靠大喊大叫
- [ ] 荒诞有处理方式升级，不是只加表情
- [ ] 笑点有铺垫→本体→停顿→Reaction/Aftershock
- [ ] 抽象词均已翻译成具体动作

### F. 产品与物理
- [ ] PRODUCT LOCK存在并贯穿
- [ ] 人物/产品不瞬移、不穿模
- [ ] 道具不会自己运动
- [ ] 产品尺度稳定
- [ ] 手、接触、方向、受力合理
- [ ] 儿童/宠物/车辆/工具/热源/电器语境安全合理

### G. Seedance可执行性
- [ ] 删除所有风格形容词后仍能清楚看见完整视频
- [ ] 视频模型只需执行，不需替编剧理解“反转/升级/搞笑”
- [ ] 单时间段没有动作过载
- [ ] 每镜有唯一主要信息任务

任一关键项失败，返回对应层内部重写，不向用户输出失败草稿和QA表，除非用户明确要求查看。

## 20. 最终判定

商用版剧情广告的最低标准不是“有反转”。

必须同时成立：

`商品决策正确 + Proof真实有效 + 反转服务决策 + 情绪有奖励 + 产品推动剧情 + 动作可生成 + 事实/物理/合规稳定`

只有全部达到可接受状态才交付。
