# 全局核心规则母版｜Core Rules SSOT

**所有风格必须继承本文件所索引的规则；本文件是规则所有权索引，不重复各模块的完整正文。** `SKILL.md` 负责路由，`styles/` 只提供创意增量。不得在风格文件中另立同名规则或降低公共验收门槛。

`G-02` 的位置锁定**不是**“所有角色始终不动”，而是位置变化必须有因果动作或明确成立的时间／空间转场。

## B. 加载与生效机制

- **任意入口**：先读本母版；识别任务阶段、项目事实和主风格。
- **大纲**：读取 G-01、G-05、G-07、G-09 对应文件及主风格；构想事件时已遵守 G-02／G-03，不凭空安排无法执行的动作；任何惊吓、Reveal或情绪转折先规划刺激来源、角色如何感知及可见反应；30秒带对白短剧在大纲阶段先规划至少12个有剧情功能的发声轮次。
- **导演分镜、真实预演、最终Prompt**：读取并执行 `references/00-project-defaults.md` 至 `references/09-four-layer-shot-gate.md` 全部公共模块，再读取一个主风格；每写一镜同步执行 G-02／G-03／G-04／G-09／G-10，画面／位置／构图／光影四层后台联审，不能写完后补救，也不向最终Prompt增加四块附录。
- **成片复盘／返修**：上述必要模块＋`evaluation/REGRESSION_CASES.md`；发现最早失败点，重编并传播后续末态。
- **规则维护**：修改唯一拥有者、回归案例和跨风格矩阵；静态校验后以真实案例做逐镜推演。

## C. 冲突处理

`当前任务确认的事实／明确创意例外 → 本母版中的共同验收 → 主风格的创意增量 → 编译器的表达压缩`。

已批准的超现实事件可以违反日常现实结果，但仍需写清事件触发、可见变化、空间连接和道具阶段状态；不能用“风格化”替代位移或接触过程。风格对 G-01～G-10 的描述若相矛盾，以对应唯一维护文件为准；先修冲突风格，而不是复制另一套核心规则。

## D. 小修订的扩散流程

1. 判断新问题是否横跨风格；是则在对应 G-ID 的唯一文件修改，不直接塞进某个风格。
2. 在 `evaluation/REGRESSION_CASES.md` 写清失败镜头、根因、可观察通过条件；在 `evaluation/CROSS_STYLE_REGRESSION.md` 为全部风格添加／更新同一规则测试。
3. 本次项目单独按 `references/PROJECT_CONTRACT.md` 写具体角色／道具空间事实，避免项目场景细节污染核心规则。
4. 更新版本与变更记录，运行静态校验及跨风格逐镜推演；没有生成实际视频时不得宣称成片通过。
