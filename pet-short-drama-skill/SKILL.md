# Pet Short Drama Director Skill

本 Skill 不是“写几个好看的镜头”，而是把一条宠物短片做成**连续发生的事件**。每个镜头必须继承上一镜的真实完成态；镜头设计、构图、运镜、音乐和台词都服从剧情与物理连续性。

## 1. 适用任务

当用户提出以下任一需求时调用本 Skill：

- 欧美宠物短剧、宠物IP剧情短片
- 豪门 / 复仇 / 身份翻盘 / 爽文式宠物短剧
- 宠物剧情带货广告
- 宠物UGC开箱 / 发现型种草短片
- 小事件大叙事、荒诞英雄、超英式宠物故事
- 已生成宠物视频的导演复盘、穿帮检查、空间连续性返修
- 将已有大纲转为专业分镜或Seedance视频提示词

如果用户没有创意，先根据账号定位构想 1 个最适合当前目标的故事；如果用户已有创意，保留核心爽点，只修叙事、空间、物理和生成风险。

## 2. 默认项目主角

当用户说“还是之前的金毛 / 用之前的主角 / 同一个宠物IP”时，默认主角为：

- 幼年浅金色金毛犬
- 圆润幼犬脸、大而湿润的深色眼睛、黑色湿鼻、自然垂耳
- 身体比例保持幼犬状态，不成人化拉长
- 行为遵循真实犬类四足运动
- 拟人来自判断、眼神、停顿、语言和有限行为，不让宠物长期站成人姿势
- 有角色参考图时，参考图优先锁定身份与外形；不自动继承原图背景、服装和动作

默认声线：可爱的幼年拟人宠物声线，略高、柔软、清亮，带轻微幼犬鼻腔共鸣和自然气声；禁止生成成年男性/成年女性的人类声线感。

## 3. 总流程

严格按以下顺序执行，不得先写成品Prompt再补连续性：

`选择风格 → 大纲 → 导演分镜 → 真实预演 → 逐镜空间状态接力 → Prompt编译 → BGM/声音 → 结尾完成态 → 最终验收`

### STEP A｜选择风格

根据任务读取一个主风格文件：

- 纯剧情IP / 小事件大叙事 / 荒诞英雄：`references/styles/ip-story-superhero-absurd.md`
- 剧情带货 / 产品体验：`references/styles/commerce-story-product.md`
- UGC开箱 / 产品发现：`references/styles/ugc-unboxing.md`
- 欧美豪门 / 复仇 / 身份翻盘爽剧：`references/styles/us-vertical-revenge-identity-flip.md`

允许混合，但必须有一个主风格，其他风格只提供局部机制。

### STEP B｜先写大纲

大纲只确定：

1. 开场已经发生什么事
2. 谁占上风
3. 什么行为把冲突做实
4. 中段什么信息改变观众认知
5. 主角怎样回击
6. 对方怎样反应
7. 最终结果怎样落地

不在大纲阶段堆摄影术语。

### STEP C｜导演分镜

每镜必须包含：

`时间 + 景别 + 摄影角度/观察位置 + 运镜 + 【构图】 + 当前空间关系 + 动作 + 必要台词/声音`

构图必须跟当前真实站位一起设计，不能为了黄金分割、中心构图等，把人物从上一镜的位置“重新摆”到新位置。

### STEP D｜真实预演

在输出最终Prompt前，必须像导演和现场执行一样，把整段从头“走一遍”。读取 `references/02-physical-previsualization.md`。

重点检查：

- 人物是否能从上一位置真实到达下一位置
- 狗与狗、狗与人、狗与道具是否有足够距离
- 接触是否遵循先接近、再接触、再响应
- 道具是否凭空出现/换手/换边
- 上台阶、进门、转身、绕行是否有可见过程
- 手和狗嘴、爪子和身体是否会互穿
- 摄影机是否真的看得到提示词声称发生的动作

发现高风险动作，优先修改动作路径，而不是在结尾加“禁止穿模”。

### STEP E｜逐镜空间状态接力

读取 `references/01-spatial-state-chain.md`。

核心公式：

`Shot N+1 State = Shot N End State`

每写完一镜，后台冻结：

- 主角位置
- 配角位置
- 各自朝向
- 当前左右/前后/高低关系
- 道具位置、归属与接触
- 正在进行的运动方向
- 摄影机所处轴线侧与观察方向
- 镜尾动作完成到哪一步

下一镜先继承，再决定是否需要位移。只要位置、朝向、高度、房间、道具归属或关键左右关系发生变化，就必须写出导致变化的动作或成立的时间/空间转场。

**摄影机换位置不能替人物完成位移。**

### STEP F｜Prompt编译

最终Prompt读取 `references/07-prompt-compiler.md`，并遵守林枫视频提示词的执行原则：

- 抽象目标先转成可拍的事件与摄影动作
- 最终模型指令不写“强钩子、高能、高级感、电影感、张力、爽感、视觉冲击、热门感、突出情绪、信息推进快”等结果评价词
- 空间动态状态写进每个镜头，不单独附“空间锁”
- 每个明确分镜都要有简短运镜
- 默认相邻非特写使用不同景别层级，摄影机明显换位但保持同一动作轴可读
- 参考图/视频只声明职责，不让多个参考争夺同一属性
- 台词必须能装进对应时间窗

如果“林枫视频提示词 Skill”可调用，则用它作为最终执行编译器；本 Skill 的剧情、空间、物理、宠物表演和结尾规则不得被覆盖。

## 4. 永久强制原则

以下原则对所有风格生效：

### 4.1 空间连续优先于漂亮单镜

分镜不是一组漂亮图片，而是一条连续的物理状态链。

**如果下一镜的新构图需要改变人物位置：先让人物完成位移，再设计新构图。**

禁止出现：上一镜主角在门外左侧，下一镜没有移动过程却出现在门外右侧；上一镜在红毯，下一镜没有走路/上台阶却已经站在楼梯上。

### 4.2 物理接触必须分阶段

高风险接触默认写成：

`接近 → 停稳/对准 → 接触 → 物体/角色响应 → 完成 → 分离`

例如人把球给狗：优先写“人把球放到石阶 → 手完全退出 → 狗再低头叼起”，而不是让手直接把球塞进狗嘴。

### 4.3 宠物的拟人不能破坏真实犬类身体

- 四足行走、奔跑、坐下、低头叼取、尾巴和耳朵反应符合真实狗
- 语言和判断可以拟人
- 不让幼犬长时间做人类站姿、挥手、复杂手部行为
- 表情以目光、耳朵、嘴角、头部、身体停顿为主

### 4.4 对嘴时必须看得到脸

宠物说话时优先让身体基本停稳，脸部清晰可见；嘴巴自然小幅开合，下颌、嘴角、舌尖和口鼻毛发跟随音节。动作特写、产品特写或复杂奔跑镜头不强塞长对白。

### 4.5 摄影机必须参与叙事

不能全程正面平视。合理使用：低机位、轻俯拍、侧前、过肩、斜后、贴地、远近变化、拉焦、推拉摇移。

运镜必须清楚可见，但只写与当前动作相符的一条主要摄影运动；不为了“丰富”而堆多重运镜。

### 4.6 构图写进每个镜头

每镜标题下直接写：

`【构图：……】`

可用：黄金分割、三分法、中心对称、引导线、框架、负空间、三角关系、前景遮挡、纵深层次。

构图服务角色关系和信息变化，不反向破坏空间连续。

### 4.7 BGM是一条连续叙事线

BGM不能只写“配合情绪”。必须描述可听变化：节拍密度、主音色、进入、加层、抽空、重拍、尾音。

对白时自动下压；关键动作声必须能听清。允许“音乐规模明显大于小事件”制造荒诞喜剧反差。

### 4.8 结尾绝不戛然而止

最后一句狠话、Reveal、产品卖点或最后一个动作都不能直接作为视频终点。

默认结尾链：

`高潮/最后一句 → Reaction反应镜头 → Consequence后果落地 → Final State完成态 → 约1秒稳定停留`

爽剧/复仇/身份翻盘优先给被反杀方一个可读反应：尴尬cᥤ񨯭、勉强维持体面、被迫接受结果，再让后果真正发生。

## 5. 最终输出格式

用户要“大纲”时：只输出故事结构，不提前堆Prompt。

用户要“分镜脚本”时：按导演分镜输出，必须有【构图】。

用户要“视频生成提示词”时，默认输出：

1. 规格
2. 参考职责
3. 必要角色/声线/持续环境
4. 连续时间轴分镜，每镜包含【构图】
5. BGM与关键环境声

不额外重复镜头清单、空间锁、情绪曲线、负面词堆。

用户上传生成成片后：先看实际视频，再按 `evaluation/REGRESSION_CASES.md` 诊断；优先局部返修，不因一个失败点推翻全部成功内容。

## 7. 交付前静默验收

最终交付前至少过一遍：

`身份一致 → 空间接力 → 物理接触 → 动作容量 → 摄影机位置 → 构图不改站位 → 对嘴 → BGM节点 → Reaction → Consequence → Final State → 停稳结束`

任一失败，回到最早出错镜头重写，并把新的完成态继续传到后续镜头。
